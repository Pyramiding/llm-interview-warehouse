# 09 · 分布式训练、并行与稳定性

> 本页 18 题为根据公开论文和官方文档编写的**原创延伸题**，不代表任何公司的面试记录。核查截止 2026-10-22。数值估算均需说明精度、状态布局、通信算法与是否包含激活；动态官方文档不等于某个项目安装版本。

<a id="d01"></a>

### D01. 数据、张量、流水线、上下文和专家并行分别切什么？

- **难度 / 适用岗位：**基础；训练、平台。
- **作答要点：**DP 切样本并同步更新；TP 切层内矩阵/张量计算；PP 切层并调度微批；CP 切序列维度并交换 attention 所需信息；EP 切 MoE 专家并路由 token。它们可组合，但进程组和维度不能随意相乘，例如专家并行常与部分数据并行维度相关联。先定义模型、world size 与拓扑，再画每组通信。[Megatron 并行指南](https://docs.nvidia.com/nemo/megatron-bridge/latest/parallelisms.html) 提供实现语义参考。
- **深入追问：**为何 TP 通常优先放节点内？长序列主要增加哪部分内存？
- **常见误区：**把所有并行都叫模型分片；忘记不同并行组可能重叠。

<a id="d02"></a>

### D02. DDP 一步训练中发生了什么，何时同步梯度？

- **难度 / 适用岗位：**基础至中等；训练工程。
- **作答要点：**各 rank 按采样方案处理数据，前向与反向本地计算；梯度就绪后按 bucket 进行集合通信，各 rank 用一致的聚合梯度更新。同步与反向可重叠，实际行为取决于框架、bucket 与动态图。需保证各 rank 一致参与集合操作、正确分片并避免非预期重复，随机化可复现。[DistributedSampler](https://docs.pytorch.org/docs/2.14/data.html#torch.utils.data.distributed.DistributedSampler)在不能整除且不丢尾时会补索引；有放回采样也可刻意设计，需明确权重语义。另见 [PyTorch 分布式通信文档](https://docs.pytorch.org/docs/2.14/distributed.html)。
- **深入追问：**为什么一个 rank 提前跳过 backward 可能令其余 rank 卡住？梯度累积为何需要控制同步时机？
- **常见误区：**以为 DDP 自动切分所有输入；每张卡重复读完整数据却认为获得了更大 batch。

<a id="d03"></a>

### D03. 定量推导：为什么 7B 模型全参训练远不止 14 GB？

- **难度 / 适用岗位：**中等；训练、容量规划。
- **作答要点：**假设每参数有 2 字节低精度权重、2 字节梯度、4 字节 FP32 主权重、8 字节 Adam 一二阶状态，则静态状态为 `16P` 字节；P=7×10^9 时约 112 GB（十进制），尚未含激活、通信桶与临时内存。不同实现可用 FP32 梯度、无主权重或不同优化器，不能把 16 当定律。先列状态再计算，而非只乘参数精度。
- **深入追问：**LoRA 训练会保留哪些底座状态？激活随 batch 和序列长怎样变化？
- **常见误区：**把推理权重容量当训练容量；GB 与 GiB 混用导致容量边界估错。

<a id="d04"></a>

### D04. ZeRO-1/2/3 的区别和代价是什么？

- **难度 / 适用岗位：**中等；分布式训练。
- **作答要点：**[ZeRO](https://arxiv.org/abs/1910.02054) 逐步分片优化器、梯度和参数；[DeepSpeed 官方教程](https://www.deepspeed.ai/tutorials/zero/) 说明阶段语义。沿用 D03 的状态假设，N 个 rank 的静态每卡量分别约 `4P+12P/N`、`2P+14P/N`、`16P/N`。这不含参数 all-gather 峰值和激活；更深分片通常带来更多通信、调度和 checkpoint 处理。
- **深入追问：**ZeRO-3 为何仍可能在某一大层 OOM？何时 ZeRO-2 更快且已足够？
- **常见误区：**把静态均分结果当峰值显存；认为 ZeRO-3 必然吞吐最高。

<a id="d05"></a>

### D05. FSDP 的 wrap 粒度、预取与重分片为什么重要？

- **难度 / 适用岗位：**进阶；训练平台。
- **作答要点：**FSDP 在计算所需单元前聚合参数，之后按策略释放/重分片。粒度太大可能产生峰值显存，太小产生许多低效小通信；预取提高重叠但也提高同时存活的参数量。[FSDP 官方文档](https://docs.pytorch.org/docs/2.14/fsdp.html) 是 API 约束来源；须明确使用 FSDP1 还是 FSDP2，不能混用选项。固定 microbatch 测内存与通信时间，再调整粒度。
- **深入追问：**共享 embedding、冻结参数和 adapter 混合会带来什么约束？checkpoint 保存为何可能峰值突增？
- **常见误区：**复制另一模型的 wrap 配置；把分片后参数的本地视图当完整权重直接保存。

<a id="d06"></a>

### D06. Tensor parallel 如何切 Transformer 的 MLP？

- **难度 / 适用岗位：**进阶；训练系统、CUDA。
- **作答要点：**对 `Y=φ(XW1)W2`，可将 W1 按输出列分片，各卡独立计算对应隐藏通道，再将 W2 按相应输入行分片，最后对局部输出求和；非线性需与分片布局匹配。[Megatron-LM](https://arxiv.org/abs/1909.08053) 是经典来源。attention 也可按头分片，但 GQA、维度整除与序列并行会改变通信；说明前向、反向各处通信才算完整。
- **深入追问：**为什么不能随意在非线性前把所有部分结果相加？列并行与行并行的 backward 如何对应？
- **常见误区：**以为分片后所有算子无需通信；只画权重分割而忽略激活布局。

<a id="d07"></a>

### D07. 流水线并行的 bubble 如何估算与改善？

- **难度 / 适用岗位：**进阶；训练系统。
- **作答要点：**简化为 p 个等时 stage、m 个 microbatch 的填充排空调度，bubble 占比约 `(p−1)/(m+p−1)`；p=8、m=32 时约 17.9%。该式不是所有 1F1B 或交错调度的精确结果。增加微批数可减少 bubble：固定微批大小时增大全局 batch；固定全局 batch 时需减小微批大小，重新衡量 kernel 效率与调度开销。负载均衡、交错与通信重叠也重要。[大规模 Megatron 论文](https://arxiv.org/abs/2104.04473) 讨论组合并行与流水线调度。
- **深入追问：**最慢 stage 多 20% 计算会怎样？embedding 和输出头应怎样分配？
- **常见误区：**只按层数均分而不按耗时；无限增加 microbatch 忽略优化与内存约束。

<a id="d08"></a>

### D08. 梯度累积是否等价于大 batch，loss 应如何归一化？

- **难度 / 适用岗位：**中等；训练算法、工程。
- **作答要点：**固定长度且每微批等权时，有效 batch 约 `microbatch×累积步数×DP`；TP/PP 不直接增加独立样本。可变长度 token 任务应按有效监督 token 总数归一化，不能简单平均各微批的平均 loss。等价还依赖 dropout、梯度裁剪、优化器更新和数值误差；学习率与 scheduler 应按实际 optimizer step 对齐。
- **深入追问：**两个 rank 的有效 token 数不同，怎样获得全局 token 平均梯度？裁剪在每个微批做会怎样？
- **常见误区：**忘记将 loss 除以累积因子；把 pad token 计入监督数量。

<a id="d09"></a>

### D09. Activation checkpointing 节约什么，代价是什么？

- **难度 / 适用岗位：**中等；训练性能。
- **作答要点：**不保存部分中间激活，在 backward 时重算前向，以计算换显存。按层、算子或选择性重算可形成不同折中；它不直接减小模型权重与优化器。需考虑随机数状态、带副作用算子和自定义 backward，先验证 loss/梯度，再测端到端吞吐。长上下文同时还可考虑高效 attention 与序列分片，不能把所有内存都归为激活。
- **深入追问：**为何重算后反而可能提高整体吞吐？腾出的空间能否让 microbatch 增大并减少流水线 bubble？
- **常见误区：**声称节省内存无计算代价；重算包含状态修改的函数却不验证语义。

<a id="d10"></a>

### D10. 定量推导：Ring all-reduce 的通信成本如何估算？

- **难度 / 适用岗位：**进阶；分布式基础设施。
- **作答要点：**简化 N 卡 ring、张量大小 M，每 rank 传输量约 `2(N−1)M/N`，时间还包括约 `2(N−1)` 步延迟和有效带宽限制。N=8、M=14 GB 时每卡约传 24.5 GB；不能直接用网卡标称速率估算实际耗时。小消息主要受延迟、拓扑与调用开销影响，大消息更受带宽影响；实际 NCCL 可能选择其他算法。
- **深入追问：**通信桶大或小如何影响反向重叠？跨节点层次化集合通信有什么价值？
- **常见误区：**把聚合数据量当每卡传输量；忽略链路竞争与通信不能完全重叠的尾部。

<a id="d11"></a>

### D11. MoE 训练为何对通信与负载均衡更敏感？

- **难度 / 适用岗位：**进阶；MoE、训练系统。
- **作答要点：**router 将 token 分发到专家，跨卡 dispatch/combine 常涉及 all-to-all；热门专家会造成计算和通信长尾。监控专家 token 分布、丢弃/填充比例、路由熵、通信耗时与每层负载。总参数影响容量，激活参数影响每 token 计算，两者都不能忽略。[DeepSeek-V3 报告](https://arxiv.org/abs/2412.19437) 提供 MoE 及训练工程的具体研究案例，但其成本与稳定性不能外推到任意集群。
- **深入追问：**容量因子增大如何影响质量与效率？专家放置能否利用节点内高带宽？
- **常见误区：**用激活参数量推算完整权重显存；只看平均专家负载掩盖最热专家。

<a id="d12"></a>

### D12. BF16、FP16、FP8 训练应该怎样讨论稳定性？

- **难度 / 适用岗位：**进阶；训练算法、系统。
- **作答要点：**分别讨论指数范围、有效精度、累加精度和硬件 kernel；FP16 容易出现梯度下溢/溢出，loss scaling 不能修复所有不稳定。FP8 需说明格式、分组缩放、统计历史与高精度保留算子。[DeepSeek-V3](https://arxiv.org/abs/2412.19437) 是低精度训练案例，不能据此认为“全链路任意算子都用 FP8”。用梯度范数、非有限值、激活分布与同种子短跑对照验证。
- **深入追问：**BF16 更大数值范围为什么仍可能 loss 发散？量化 scale 跟不上分布变化会怎样？
- **常见误区：**只列位数；把存储 dtype 与乘法、累加、优化器 dtype 混为一谈。

<a id="d13"></a>

### D13. MFU、HFU 和 tokens/s 应怎样解释？

- **难度 / 适用岗位：**中等至进阶；性能、负责人。
- **作答要点：**MFU 用有效模型计算与硬件理论能力比较；HFU 可能计入重算等实际硬件工作，必须公布定义。dense Transformer 的训练 FLOPs 常用 `6ND` 作粗估，长序列 attention、词表和非标准架构需修正。以“非 padding 的训练 token”计算吞吐，结合收敛质量比较；提高 MFU 但减少有效学习 token 或伤害质量不一定有收益。[Llama 3 报告](https://arxiv.org/abs/2407.21783) 可供阅读规模化训练的报告方式。
- **深入追问：**重算增加时为何 HFU 可能升高而训练变慢？FP8 峰值与 BF16 峰值能混用吗？
- **常见误区：**给 MFU 百分比却不写 FLOPs 公式与峰值口径；比较不同模型的原始 tokens/s。

<a id="d14"></a>

### D14. 系统设计：如何规划一个可恢复的多节点预训练任务？

- **难度 / 适用岗位：**高级；训练架构、平台。
- **作答要点：**明确模型、token 预算、精度、网络拓扑和检查点恢复目标；先做单卡/单节点正确性，再扩容评估通信与数据供应。按内存选择分片，按拓扑配置 TP/PP/DP；保存权重、优化器、scheduler、随机状态、采样器/数据位置与配置。检查点需原子发布、校验和及定期恢复演练，避免“保存成功但无法恢复”。
- **深入追问：**恢复后 world size 改变如何重分片？如何确保不重复或跳过大量训练数据？
- **常见误区：**只保存模型权重却称可继续训练；没有容错预算与慢节点处理。

<a id="d15"></a>

### D15. 排障：多卡训练卡在 collective，如何定位？

- **难度 / 适用岗位：**进阶；训练运维。
- **作答要点：**先找所有 rank 的首个错误，不把最后的 timeout 当根因；检查进程存活、集合操作顺序、tensor shape/dtype、分支与数据迭代是否一致。再用最小集合通信验证 GPU 互联、网卡、共享内存及驱动，参考 [NCCL 排障文档](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/troubleshooting.html)。保留 rank、时间戳和错误链后再调整环境参数。
- **深入追问：**一个 rank 数据加载失败为什么表现为其他 rank NCCL 超时？能否靠无限增大 timeout 解决？
- **常见误区：**盲目更换一串 NCCL 环境变量；只查看 rank 0 日志。

<a id="d16"></a>

### D16. 排障：从 8 卡扩到 64 卡，吞吐只提高两倍，如何分析？

- **难度 / 适用岗位：**进阶；性能优化。
- **作答要点：**区分强扩展与弱扩展：总 batch 固定时每卡工作减少、通信比例提高；每卡 batch 固定时又改变优化过程。按时间线拆计算、通信、数据读取、同步等待与 checkpoint；检查跨节点拓扑、最慢 rank、padding 浪费和 CPU 线程。只对真实瓶颈改 bucket、并行布局或输入管线，再报告扩展效率与质量是否等价。
- **深入追问：**单节点很好、两节点骤降优先查什么？怎么识别一张慢卡拖住全体？
- **常见误区：**只比较 GPU 平均利用率；改变 batch 和数据后仍宣称纯系统加速。

<a id="d17"></a>

### D17. 排障：训练突然出现 NaN 或 loss spike，怎样缩小范围？

- **难度 / 适用岗位：**进阶；训练稳定性。
- **作答要点：**保存问题 batch、前后 checkpoint、随机状态和各 rank 日志，按数据、优化器、精度、算子与通信分层排查。检查异常长度、错误 mask、零有效 token、学习率跳变、梯度爆炸、scale 与非有限激活。用高精度小样本和禁用可疑 fused kernel 对照；修复后验证恢复点，不只用回滚掩盖重复触发条件。
- **深入追问：**仅一个 rank 出 NaN 后 all-reduce 会怎样？loss 正常但参数已有 Inf 可能吗？
- **常见误区：**不保存样本就重启；把所有 spike 都归因于学习率太大。

<a id="d18"></a>

### D18. 一个优秀的分布式训练项目复盘应有哪些证据？

- **难度 / 适用岗位：**高级；训练、平台负责人。
- **作答要点：**说明基线模型、精度、并行布局、硬件与数据；报告收敛曲线、有效 token 吞吐、峰值显存、扩展效率、故障频率与恢复耗时。证明系统改动没有改变目标函数或样本权重，给出消融、失败案例和可复现实验配置。把论文功能、框架已有能力和个人贡献清楚区分，成本包含试验、失败与存储。
- **深入追问：**如果 30% 加速来自减少 padding，如何说明？“稳定跑了一天”能否证明长稳可靠？
- **常见误区：**只有最终 loss 和总卡数；未做恢复演练却声称有容错能力。
