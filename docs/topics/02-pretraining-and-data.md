# 预训练、数据工程与 Scaling Laws

> 18 道原创延伸题；根据公开研究整理，不声称是企业真题。核验截止：2026-10-22。回答以可验证的设计取舍为主，不把某个模型的单次实验推广为普遍定律。

## 面试表达框架

回答数据题时，顺序可用“目标能力 → 数据来源与粒度 → 清洗和采样 → 受控实验 → 成本及失败回滚”。回答 scaling 题时先区分训练算力最优、部署总成本最优和受数据约束的最优。近期可复现入口是 FineWeb、Dolma 与 DataComp-LM；2025 年公开模型报告用于补充实际训练阶段设计。

<a id="p01"></a>

### P01. 预训练、持续预训练、SFT 分别优化什么？

**难度 / 岗位：** 基础；算法、训练、应用。

**作答要点：** 自回归预训练在广泛文本上学习条件分布；持续预训练通常沿用语言建模损失，调整领域、语言或长度分布；SFT 在示范任务上强化条件响应，常只对 assistant token 计损失。三者没有由优化器定义的绝对边界，关键是数据分布、监督范围和预期行为。领域知识缺口可考虑持续预训练，格式与流程偏差可考虑 SFT；应通过分项评测验证。实际阶段示例见 [Llama 3](https://arxiv.org/abs/2407.21783)。

**深入追问：** 新增法律领域知识时，为什么还要看通用能力回归、知识时效和数据授权？若只是每周变化的业务事实，参数更新是否合算？

**常见误区：** 把所有训练都叫 SFT；认为完成预训练就天然具备聊天角色边界。

<a id="p02"></a>

### P02. 如何解释 Chinchilla scaling law，哪些条件不可省？

**难度 / 岗位：** 进阶；预训练、研究。

**作答要点：** 一种经验拟合为 `L(N,D)=E+A/N^α+B/D^β`，与训练算力近似 `C≈6ND` 联立，寻找固定 C 下 N、D 的分配。Chinchilla 在其实验范围发现模型和训练 token 应近似同比例增长。常见“每参数约 20 token”是特定拟合的量级经验，不是强制配比；数据质量、架构、学习率计划、重复数据和推理预算会改变最优点。见 [Chinchilla](https://arxiv.org/abs/2203.15556)。

**深入追问：** 推导 `D∝N^(α/β)`，因此当 α≈β 时 D 近似正比于 N；为什么不能只报“参数越大越好”？

**常见误区：** 把训练算力最优当成商业部署总成本最优；不说明 N、D 的单位和拟合范围。

<a id="p03"></a>

### P03. 为什么不少模型选择超过训练算力最优点继续训练？

**难度 / 岗位：** 进阶；训练、推理、研究。

**作答要点：** 总成本可写作 `C_total=C_train+Q·C_infer`，Q 为未来服务量。小一些的模型训练更多 token，可能增加一次性训练成本，却减少每次推理开销；当 Q 很大时更有利。还应考虑延迟、显存、并发及质量门槛，而非只看 FLOPs。比较方案时固定预期质量或固定服务预算，不能同时偷换模型、数据和评测。部署意识的训练讨论可参考 [Llama 3](https://arxiv.org/abs/2407.21783)。

**深入追问：** 设方案 A 多花 100 万训练费、每次请求省 0.001 元，约 10 亿请求达到简单财务盈亏平衡；哪些现实因素会改这个数？

**常见误区：** 把 overtraining 一律叫过拟合；只根据参数量估计所有硬件上的延迟。

<a id="p04"></a>

### P04. 给定参数、token 和集群，如何估算训练时间？

**难度 / 岗位：** 进阶；训练、系统。

**作答要点：** 对常见 dense Transformer，粗估 `C≈6ND`，但长上下文 attention、embedding、重算及稀疏结构要修正。假设 N=7B、D=1T，则约 `4.2×10²² FLOPs`。若 128 张卡每卡在选定精度的峰值 500 TFLOP/s，模型 FLOPs 利用率 MFU 为 40%，有效算力为 `2.56×10¹⁶ FLOP/s`，理想耗时约 19 天；再加入故障、评测和检查点时间。近似起点见 [Chinchilla](https://arxiv.org/abs/2203.15556)。

**深入追问：** MFU 与硬件 FLOPs 利用率为何可能不同？统计中是否把激活重算计入有效模型 FLOPs？

**常见误区：** 混淆 FLOPs 总量与 FLOP/s；把峰值乘卡数直接当可持续算力。

<a id="p05"></a>

### P05. 怎样把 Common Crawl 变成可训练的数据集？

**难度 / 岗位：** 进阶；数据、预训练。

**作答要点：** 可分为来源登记、网页正文抽取、编码/语言识别、质量与安全过滤、去重、训练评测去污染、分桶混合和 token 化打包。每阶段保留版本、过滤原因、抽样审查与 token 留存率，便于定位哪些处理导致能力变化。过滤顺序会影响统计与成本，不能只列工具名。FineWeb 公开了大规模网页数据处理及消融，是学习管线的起点。见 [FineWeb](https://arxiv.org/abs/2406.17557)。

**深入追问：** 怎样证明“高质量过滤”真正有效？答固定训练预算及模型，对比下游任务、领域覆盖和重复率。

**常见误区：** 用清洗后 token 更多证明质量更高；仅保存最终文本而丢失数据来源。

<a id="p06"></a>

### P06. 精确去重、近似去重、子串去重分别解决什么问题？

**难度 / 岗位：** 进阶；数据、训练。

**作答要点：** 文档哈希适合完全一致内容；基于 shingles/MinHash 的近似方法寻找高重合文档；后缀数组等子串方法可定位跨文档长重复片段。模板导航、镜像页面和爬取版本会浪费预算并放大记忆。去重也可能误删短文本、代码模板与少数语言，因此必须按长度、来源和语言审查误杀率。公开研究显示其设定下去重改善记忆与评估重合。见 [Deduplicating Training Data](https://arxiv.org/abs/2107.06499)。

**深入追问：** Jaccard 阈值为什么应与分词、shingle 长度共同记录？同一篇文章的翻译是否会被识别？

**常见误区：** 认为一个 MD5 就完成语义去重；把所有重复都视为有害噪声。

<a id="p07"></a>

### P07. 训练集与 benchmark 去污染应如何实施？

**难度 / 岗位：** 进阶；数据、评测、研究。

**作答要点：** 建立版本固定的评测保护集合，检查题干、答案、解释及近似改写；可结合标准化后的 n-gram、精确子串和语义匹配，对命中样本人工复核。按时间和来源拆分，并保留未命中评测作为旁证。不能因无精确重合就断言没有泄漏，答案模板、翻译和教师生成也可能带来污染。出处见 [去重研究](https://arxiv.org/abs/2107.06499)。

**深入追问：** 删除 benchmark 题干后，含详细题解网页是否仍可能泄漏？如何避免去污染把整个相关学科删掉？

**常见误区：** 将模型答对知名题等同于记忆证据；只在最终模型上检测，不审查数据。

<a id="p08"></a>

### P08. 如何设计中文、多语言与代码数据混合？

**难度 / 岗位：** 进阶；预训练、数据。

**作答要点：** 从目标用户语言、能力需求与可用优质数据量出发，按 token 而非文档数量设预算，记录 tokenizer 压缩率。温度采样 `q_i∝p_i^(1/τ)` 可平滑大语种优势，但过度上采样小语种会增加重复。按语言、代码、数学等切片评估，并观察通用能力与目标能力的 Pareto 权衡。混合多源语料的公开案例见 [Dolma](https://arxiv.org/abs/2402.00159)、[Qwen3](https://arxiv.org/abs/2505.09388)。

**深入追问：** `τ>1` 为什么使分布更平？低资源语言的高质量样本少，何时停止重复采样？

**常见误区：** 直接照搬另一模型未完全公开的配比；中文文档占 50% 就宣称中文 token 占 50%。

<a id="p09"></a>

### P09. Tokenizer 的设计为什么会影响算力和多语言公平性？

**难度 / 岗位：** 基础；算法、数据、应用。

**作答要点：** tokenizer 通常包含规范化、预分词、子词模型及后处理；BPE 合并高频片段，byte-level 设计可改善字符覆盖，但不代表所有语言压缩率相同。更大词表可能缩短序列，也增加 embedding/输出头成本。比较时用同一原始文本统计 tokens/byte、特殊符号保留、代码空白、罕见字与跨语言效率。流程见 [Hugging Face Tokenizers](https://huggingface.co/docs/tokenizers/main/en/pipeline)。

**深入追问：** 同一中文文档从 4000 token 降到 2500 token，会怎样影响上下文覆盖和 attention 成本？

**常见误区：** 把中文一个字当成恒定一个 token；认为换 tokenizer 不需要处理 embedding 兼容性。

<a id="p10"></a>

### P10. Sequence packing 怎样避免 padding 浪费与样本串扰？

**难度 / 岗位：** 进阶；训练、数据。

**作答要点：** 将短文档打包到固定长度以提高有效 token 比例；可用 EOS 分隔连续文档，也可使用 block diagonal mask 阻止跨样本注意力。两者训练语义不同：EOS 本身不是硬隔离。SFT 还必须同步更新 labels mask、位置索引和角色边界。应显式记录是否允许文档之间条件化，以及损失统计分母。聊天序列约定见 [Chat templates](https://huggingface.co/docs/transformers/main/chat_templating)。

**深入追问：** 文档 A 之后的文档 B 是否允许看 A？重置 position id 与重置 attention mask 是否等价？

**常见误区：** 只拼 input_ids 而忘记拼 labels；把 padding token 的 embedding 置零当成完成 mask。

<a id="p11"></a>

### P11. 质量分类器的阈值为什么必须通过训练消融确定？

**难度 / 岗位：** 研究；数据、预训练。

**作答要点：** 分类器的“教育性”“可读性”等分数是代理指标，可能偏好英语教材风格，损伤口语、少数语言和代码。先在分层样本上检查精度及召回，再固定训练 token/算力比较阈值与混合策略，防止把数据规模差异当质量收益。也要报告过滤后覆盖和重复率。FineWeb-Edu 与 DCLM 提供了可研究的筛选路径，不能将其单项增益直接迁移到所有任务。见 [FineWeb](https://arxiv.org/abs/2406.17557)、[DataComp-LM](https://arxiv.org/abs/2406.11794)。

**深入追问：** 在知识问答涨分、对话质量下降时，如何判断是数据偏差还是指标权重问题？

**常见误区：** 用分类器分数平均值作为唯一训练目标；把高 perplexity 文本全部判成垃圾。

<a id="p12"></a>

### P12. 合成数据有什么价值，如何避免循环训练退化？

**难度 / 岗位：** 进阶；数据、研究、后训练。

**作答要点：** 合成数据可补充解释、代码测试和稀缺任务覆盖；质量取决于教师能力、提示多样性、可验证性和筛选。保留真实数据、追踪生成来源、做去重及独立评测；对数学/代码优先用执行器核验。递归使用模型输出替代真实分布可能丢失尾部信息，但不能据此声称一切合成数据都导致崩塌。见 [Model Collapse 研究](https://arxiv.org/abs/2305.17493)、[Textbooks Are All You Need](https://arxiv.org/abs/2306.11644)。

**深入追问：** 教师生成后再由同一教师评分，会引入哪些同源偏差？如何用真实用户长尾失败集检验？

**常见误区：** 只报生成条数，不报有效、独特、通过核验的样本量；把教师自信当正确性。

<a id="p13"></a>

### P13. 数据不足时重复训练，怎样判断收益递减？

**难度 / 岗位：** 进阶；预训练、研究。

**作答要点：** 区分 unique token 与总 seen token；重复多 epoch 可以继续降训练 loss，但不等于同量新数据收益。建立独立同分布和目标任务验证集，对重复次数、质量、模型大小做受控比较；记录验证损失与记忆/抽取风险。数据受限的 scaling 研究说明需要显式建模重复数据，不能把 seen token 简单全部当新信息。见 [Scaling Data-Constrained Language Models](https://arxiv.org/abs/2305.16264)。

**深入追问：** 500B unique token 重复两遍，与 1T unique token 的训练预算相同吗？质量与学习率计划还需控制哪些变量？

**常见误区：** 训练 loss 持续下降就认为没过拟合；把重复采样次数隐藏在 token 总量里。

<a id="p14"></a>

### P14. 持续预训练如何降低灾难性遗忘？

**难度 / 岗位：** 进阶；领域模型、训练。

**作答要点：** 小学习率、目标域与通用语料重放、分阶段采样和检查点选择都是可实验的手段；没有一种能无条件消除遗忘。建立通用、目标域、语言及安全回归集合，比较领域收益与通用损失；领域验证 loss 不应成为唯一选择标准。若只需要时效事实，应比较 RAG 成本。公开的领域适应起点见 [Don't Stop Pretraining](https://arxiv.org/abs/2004.10964)。

**深入追问：** 如何区分遗忘、chat template 不匹配和生成参数变化？为何只换一个更小学习率仍可能丢能力？

**常见误区：** 把“冻结部分参数”当作知识不会遗忘的证明；没有通用回归集。

<a id="p15"></a>

### P15. 训练 loss 突然尖峰，如何分层排查？

**难度 / 岗位：** 进阶；训练、系统。

**作答要点：** 先定位尖峰步的样本、长度、token 分布和各 rank 是否一致，排查坏编码、重复长串、空 target、数据跳变；再看学习率、梯度范数、激活范围和优化器状态；最后看通信、硬件与检查点恢复。保留异常批次并重放，区分可恢复尖峰与后续持续发散。大规模训练报告可参考 [OLMo](https://arxiv.org/abs/2402.00838)。

**深入追问：** 只某一 rank NaN 与所有 rank 同步尖峰各提示什么？跳过坏 batch 后如何保证可复现？

**常见误区：** 一见尖峰就断言数据质量差；直接降低学习率而不保存证据。

<a id="p16"></a>

### P16. 怎样设计可信的预训练小规模消融？

**难度 / 岗位：** 研究；研究、数据、训练。

**作答要点：** 固定模型、tokenizer、训练 FLOPs、评测与尽可能一致的随机因素，只改变待研究的数据操作；若比较数据量，则另设固定步数与固定预算实验。报告多个切片、方差及代价，避免挑最高一个 checkpoint。小模型结论迁移到大模型需要复核，尤其结构与数据质量交互项。DataComp-LM 的受控数据实验思路可作起点。见 [DCLM](https://arxiv.org/abs/2406.11794)。

**深入追问：** 固定 token 和固定 FLOPs 哪个更适合比较不同长度分布？评测集合何时锁定？

**常见误区：** 同时换数据、模型和学习率；反复用同一 benchmark 调参数后再把它当无偏测试集。

<a id="p17"></a>

### P17. 一个可复现的训练检查点需要包含什么？

**难度 / 岗位：** 进阶；训练、系统。

**作答要点：** 不只权重，还需优化器状态、调度器、global step、累计梯度状态（若中途保存）、随机数状态、数据游标与采样器、tokenizer、配置及代码/数据版本。分布式恢复需考虑 world size 与 shard 映射变化。验证标准是恢复后下一批数据与短程损失轨迹符合约定，而非“能成功 load”。开放训练资产案例见 [OLMo](https://arxiv.org/abs/2402.00838)。

**深入追问：** 只恢复模型权重为何会造成损失跳变？流式数据源变更后如何定义恢复语义？

**常见误区：** 把 inference checkpoint 当完整训练恢复点；在断点续训时重复或跳过大量数据。

<a id="p18"></a>

### P18. 读 Llama 3、DeepSeek-V3、Qwen3 报告，面试中应如何比较？

**难度 / 岗位：** 研究；预训练、研究、技术负责人。

**作答要点：** 做对照表：dense/MoE、总参数/激活参数、数据与 tokenizer、训练阶段、上下文、精度、硬件与评测协议。明确未公开项，不将宣传成本直接等同全生命周期研发成本；区分 base、instruct、thinking 版本。Qwen3 的公开报告包含 dense/MoE 与 thinking/non-thinking 设计，可用来讨论训练和服务目标的联合选择。参见 [Llama 3](https://arxiv.org/abs/2407.21783)、[DeepSeek-V3](https://arxiv.org/abs/2412.19437)、[Qwen3](https://arxiv.org/abs/2505.09388)。

**深入追问：** 为什么同一榜单不能直接证明某个数据配方优于另一个？哪些结论需要实际复现消融？

**常见误区：** 将 API 产品名当固定训练检查点；把论文修订年份当模型首次发布年份。
