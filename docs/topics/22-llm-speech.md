## 系统链路：数据、基线、机制与验收

下表是可供面试设计的原创工程拆解；每个环节需用实际约束验证，不能由单个离线指标推断业务收益。

| 环节 | 数据 / 标签 | 传统基线 | LLM 结合机制 | 评测 / 成本 |
|---|---|---|---|---|
| 采集与标注 | 授权音频、说话人、设备、转写规范 | 人工转写、强制对齐 | 弱监督清洗和转写候选辅助 | 音文错配、说话人泄漏；每小时标注成本 |
| 前端与端点 | 音频帧、噪声、回声、结束标注 | 降噪/AEC、VAD、端点模型 | 语义端点辅助判断 | 截断/误触发；前瞻毫秒和设备负载 |
| 流式识别 | partial/final文本、时间戳、热词 | CTC/RNN-T或流式封装 | ASR大模型+稳定前缀策略 | WER/CER、关键实体；首文本/最终延迟 |
| 理解与状态 | 用户意图、已确认槽位、语音韵律 | NLU分类器、状态机 | LLM多轮理解或原生语音理解 | 槽位/任务正确；上下文与KV开销 |
| 工具执行 | 确认记录、业务状态、幂等键 | 事务服务与权限网关 | 模型提议动作与解释结果 | 错误动作、未知状态恢复；工具p99 |
| 语音合成 | 授权音色、文本、发音词典 | 声学模型+vocoder | 自回归codec/flow matching TTS | MOS、可懂度、数字读法；首音/RTF |
| 播放与打断 | 已播位置、用户插话、取消信号 | 双工通道、AEC、取消协议 | 语音模型支持同时听说 | 误打断/恢复一致；取消到静音毫秒 |
| 服务与评测 | 会话时序、网络、设备、成本账单 | 长连接调度、负载测试 | 分层路由、上下文压缩 | 任务成功/端到端p99；每成功会话分钟成本 |

## 项目验收证据清单

提交设计或复盘时，至少准备以下可核查材料；不提供内部数据和个人信息。

1. 说话人/设备隔离的授权音频清单，说明采样率、语言、噪声、转写和归一化规则。
2. 同音频条件下级联/原生路线对照，报告实体准确、WER/CER、任务成功与样本量。
3. 带时间戳的端点、ASR、LLM、TTS、网络和播放延迟瀑布；p50/p95/p99单位统一为毫秒。
4. 长停顿、背景说话、回声、否定、长数字、打断中工具超时的会话回放。
5. 同硬件并发压测及每会话分钟账单，记录授权音色、动作权限和断线恢复。

### SP01. ASR→LLM→TTS 与原生语音模型如何选？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 级联便于文本审计、工具调用与替换，原生语音可保留韵律、重叠与非语言信息但更难定位错误。以相同设备、语言、噪声和任务比较正确率、端到端延迟与资源；先建级联强基线，再用原生方案验证具体瓶颈，不按架构新旧选择。
- **深入追问：** 客服要求逐字审计，原生方案如何补足？
- **常见误区：** 语音自然就等于任务可靠。
- **一手参考 / 适用边界：** [Moshi: a speech-text foundation model for real-time dialogue](https://arxiv.org/abs/2410.00037)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP02. 语音训练数据如何切分？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 按说话人、会话、设备、地域与时间隔离，避免同一说话人的相邻片段跨集合。记录转写规范、采样率、语言与授权用途，去掉重复和错配音文；对静音、噪声、音乐和口音分层采样。公开音频可访问不等于允许任意克隆或训练。
- **深入追问：** 同一录音不同切块会泄漏什么？
- **常见误区：** 随机切音频片段即可测泛化。
- **一手参考 / 适用边界：** [Robust Speech Recognition via Large-Scale Weak Supervision](https://arxiv.org/abs/2212.04356)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP03. WER 降低为什么业务未改善？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** WER=(替换+删除+插入)/参考词数；中文需说明 CER 或分词规则，分母为零的静音另计。人名、金额、否定词的错误代价不同，补关键实体与任务完成率。报告噪声/口音切片、归一化规则和延迟，同条件比较，不以平均 WER 替代可执行准确率。
- **深入追问：** “不要退款”识别成“要退款”如何计业务风险？
- **常见误区：** 删掉标点数字差异后只报最漂亮指标。
- **一手参考 / 适用边界：** [Robust Speech Recognition via Large-Scale Weak Supervision](https://arxiv.org/abs/2212.04356)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP04. 流式 ASR 如何处理部分结果反复改写？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** Whisper 原版并非为实时转写设计；流式封装可参考 LocalAgreement。区分临时与稳定前缀，保留时间戳和修订版本；下游只在可撤销阶段消费临时文本，关键动作等最终确认。比较 chunk、lookahead 与稳定性，记录首次文本、最终文本延迟和回改率。不同切块策略需统一音频和端点条件。
- **深入追问：** 用户话没说完就识别出取消订单怎么办？
- **常见误区：** 把第一个 partial 当最终指令。
- **一手参考 / 适用边界：** [Turning Whisper into Real-Time Transcription System](https://arxiv.org/abs/2307.14743)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP05. VAD 与端点检测怎样权衡？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** VAD 判断语音存在，端点推断用户是否完成发言，语义和停顿共同影响。短静音阈值降低等待却截断犹豫与长数字，长阈值增加轮次延迟；构造口音、噪声、长停顿和插话集，测截断率、误触发与结束后等待时间。业务关键槽位缺失时追问。
- **深入追问：** 用户停顿两秒继续报手机号怎么处理？
- **常见误区：** 一个静音阈值适合所有场景。
- **一手参考 / 适用边界：** [Moshi: a speech-text foundation model for real-time dialogue](https://arxiv.org/abs/2410.00037)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP06. 实时语音延迟预算如何分解？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 从用户音频结束到首个可听响应测端到端 p50/p95/p99，再拆上传、端点、ASR、LLM 首 token、TTS 首音频与播放缓冲。区分算法前瞻和排队，稳态吞吐不等于首响应；允许推测生成但动作和敏感内容先确认。记录设备与网络条件。
- **深入追问：** 模型快了但体验慢，先查哪项？
- **常见误区：** 把 LLM TTFT 当语音端到端延迟。
- **一手参考 / 适用边界：** [Moshi: a speech-text foundation model for real-time dialogue](https://arxiv.org/abs/2410.00037)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP07. 如何实现可靠打断与取消？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 播放与监听双通道，识别真正用户插话而非回声/背景声；触发后停止播放、取消尚未提交生成并标记已播放位置。对已提交工具动作使用事务状态与补偿，不能只清空音频；记录打断响应、误打断和恢复一致性。
- **深入追问：** 退款已经执行时用户说“等等”怎么办？
- **常见误区：** 停止 TTS 就等于撤销业务动作。
- **一手参考 / 适用边界：** [Moshi: a speech-text foundation model for real-time dialogue](https://arxiv.org/abs/2410.00037)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP08. TTS 自回归与 flow matching 怎样比较？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 自回归逐步生成与非自回归/flow 方法在并行性、对齐和采样步数上取舍不同。固定文本、参考音频、硬件与输出质量比较首音、实时因子和失败率；F5-TTS 是 flow matching 路线案例，不代表所有配置都更快。增加步数需测边际质量与时延。
- **深入追问：** 减少采样步数应看哪些退化？
- **常见误区：** 模型并行生成就默认能低延迟流式。
- **一手参考 / 适用边界：** [F5-TTS: A Fairytaler that Fakes Fluent and Faithful Speech with Flow Matching](https://arxiv.org/abs/2410.06885)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

<a id="sp09"></a>

### SP09. 语音 codec token 率如何影响系统？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 帧率、码本数和每码本位数决定近似码率，LLM 序列长度还取决于码本的串行/并行组织。比较保真度、可懂度、首包、上下文占用与生成稳定性；压缩降低 token 数可能损失声学细节。不要混淆压缩后的文件大小和语言模型实际步数。
- **深入追问：** 多个码本全串行会增加多少步？
- **常见误区：** 码率减半必然让端到端推理时间减半。
- **一手参考 / 适用边界：** [Moshi: a speech-text foundation model for real-time dialogue](https://arxiv.org/abs/2410.00037)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP10. TTS 如何评价自然度和可懂度？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** MOS 需盲听、随机顺序、说话人/文本平衡和评价者质量控制，并报告置信区间。补充转写错误、说话人相似、韵律、多音字/数字读法和长文本失败率；ASR 复转写是代理，受识别器偏差影响。音色相似不等于内容忠实。
- **深入追问：** MOS 高但金额读错应如何判？
- **常见误区：** 用单一相似度分数证明合成质量。
- **一手参考 / 适用边界：** [F5-TTS: A Fairytaler that Fakes Fluent and Faithful Speech with Flow Matching](https://arxiv.org/abs/2410.06885)；参考其机制或评价框架，具体业务方案与阈值需另行验证。

### SP11. 语音克隆如何定义授权与边界？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。

- **深入追问：** 已有参考音频但没有用途授权能否使用？

### SP13. 语音情绪识别为何要谨慎？

### SP14. 多语言、口音和 code-switch 如何评测？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 分别组织语言、方言、口音与混说集，保留人群和设备分布，统一转写标准。检查语言识别切换、专名、数字和翻译漏失，按会话报告而非只汇总词数；训练重采样与热词增强要验证其他语言回归。不可用英语成绩推断中文客服质量。
- **深入追问：** 同一句话混合英语品牌名如何记错？
- **常见误区：** 把翻译正确率当原语识别率。

### SP16. 实时服务怎样容量规划和降级？

- **难度 / 适用岗位：** 中高级至高级；语音算法、实时交互、推理服务。
- **原创作答要点：** 用活跃会话数、音频帧率、生成占空比、KV 与 codec 缓冲估算资源，压测长连接、弱网、突发与断线恢复。批处理需受首音/帧截止时间约束；降级可改短回答、级联或文字通道，并保持工具状态一致。报告每会话分钟总成本而非单 token 成本。
- **深入追问：** 并发不变但用户更爱插话，负载如何变？
- **常见误区：** 只按请求 QPS 规划长连接语音服务。
