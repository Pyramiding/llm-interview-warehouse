# 11. 推理模型与测试时计算

> **题目性质：原创研究延伸题，不是企业真题摘录。** 适用于算法研究、后训练、推理系统和 Agent 岗。文中方案与实验建议是编者整理，不表示引用论文已经证明。资料核查截止 **2026-10-22**；主要覆盖 2023—2026，并保留必要的 2022 年经典。论文结果受版本、模型和预算约束，不作为当前排行榜。

阅读路线：T01—T04 建立概率与指标概念，T05—T10 讨论训练，T11—T17 讨论推理与可信性，T18 练习研究评审。

<a id="t01"></a>

### T01. 你怎样判断一个模型的“推理能力”变强，而不只是答案格式变好？

- **难度 / 适用岗位：** 中级；算法、研究、评测。
- **原创作答要点：** 先定义任务：多步数学、规则组合、规划或程序执行不能混成一个能力。把正确率与格式合法率分开；在同一提示、工具权限、样本数和 token / 时间预算下比较。设计数值替换、条件交换、无关信息、组合外推等对照，判断是否依赖记忆或表面模式；再用人工错误分类区分事实缺失、建模错误、计算错误和验证错误。结论只能覆盖被测分布。
- **深入追问：** 若原题涨分、同构改写掉分，下一轮训练与数据审计怎么安排？
- **常见误区：** 把更长回答、频繁说“重新检查”或单个竞赛分数当成一般推理证明。

<a id="t02"></a>

### T02. CoT 为什么可能有效？从概率分解解释它的能力与局限。

- **难度 / 适用岗位：** 中级；算法、后训练。
- **原创作答要点：** 令中间文本为 z、答案为 y，生成过程建模 p(z,y|x)，而目标答案概率为 Σ_z p(z,y|x)。中间表示提供可继续计算的上下文，把复杂映射展开成多步；但贪心选一条 z 不等于求边缘概率，早期错误也会污染后续。经典 [CoT 论文](https://arxiv.org/abs/2201.11903)说明了示例式推理提示的效果，不能据此断言输出文字等同于模型内部计算。应测试无 CoT、简短解释、长解释与相同预算采样。
- **深入追问：** 推理轨迹很流畅但答案错误，你会怎样定位收益来自计算还是文体？
- **常见误区：** 把 CoT 当成模型架构，或认为任何模型、任何任务都应逐步输出。

<a id="t03"></a>

### T03. Self-consistency 与普通多数投票有什么关系？为什么收益会饱和？

- **难度 / 适用岗位：** 中级；算法、推理服务。
- **原创作答要点：** [Self-Consistency](https://arxiv.org/abs/2203.11171)通过多样轨迹采样，再聚合归一化后的最终答案。有效性依赖正确答案在聚合分布中的质量和路径多样性；同一模型共享错误时，增加样本不会消除系统偏差。投票前需统一单位、分数表示和答案抽取，同时防止把等价答案拆票。报告不同 N 下的收益、错误相关性、成本和不确定性；多数票比例不是校准后的正确概率。
- **深入追问：** 64 个候选答案都一致，是否还需要验证器？
- **常见误区：** 用独立同分布且单样本正确率大于 0.5 的直觉，无条件解释真实相关样本。

<a id="t04"></a>

### T04. pass@k、best-of-N 和最终部署准确率为什么不能混用？

- **难度 / 适用岗位：** 中级；评测、研究、代码模型。
- **原创作答要点：** pass@k 衡量 k 个样本中至少一个正确的覆盖能力；best-of-N 还需要可实施的选择器。按相同采样协议独立生成 n 个候选，其中 c 个通过测试，且 n≥k≥1 时，常用估计为 `1−C(n−c,k)/C(n,k)`；n−c<k 时分子组合数按0处理。[HumanEval论文](https://arxiv.org/abs/2107.03374)给出该估计，独立生成不等于候选必须互异。实际效果受生成器覆盖率与选择器精度共同限制；“用标准答案挑最好”只提供 oracle 上界。比较时应把验证器调用、执行、重试也计入预算。
- **深入追问：** 覆盖率很高却选不出正确解，应改生成器、验证器还是预算分配？
- **常见误区：** 把 pass@64 写成单次用户成功率，或免费使用测试集答案筛选。

<a id="t05"></a>

### T05. 过程奖励 PRM 与结果奖励 ORM 的监督对象、成本和风险有何不同？

- **难度 / 适用岗位：** 高级；奖励模型、后训练。
- **原创作答要点：** ORM 评价终局，标注通常较粗；PRM 给中间步骤提供局部信号，可用于剪枝和定位错误，但步骤切分、可替代解法与标签一致性更难。[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)在特定数学设置比较了两者；实验优势不能直接推广到开放创作。聚合 PRM 分数要说明采用最小值、乘积还是学习式汇总，并检查对长短轨迹的偏置。验证器要用独立题目验证，避免生成器和裁判共错。
- **深入追问：** 一个局部步骤不可独立判真，但完整证明正确，如何标注？
- **常见误区：** 将语言流畅度当成局部逻辑正确性，或假定逐步打分自动解决奖励攻击。

<a id="t06"></a>

### T06. 只有终局 0/1 奖励，为什么仍可能学出有用的中间行为？

- **难度 / 适用岗位：** 高级；RL、推理研究。
- **原创作答要点：** 策略梯度把成功轨迹中的动作概率整体提高，重复采样可使有利的搜索、检查等模式获得间接信用；不要求每一步都有人工标签。但延迟奖励方差高，偶然正确和无效长文本也可能获奖。讨论可学习前提：基础策略已有非零成功概率、题目可验证且难度合适、探索足够。设计固定数据与算力下的 SFT、RL、拒绝采样对照，观察未见题型与轨迹效率。
- **深入追问：** 全组样本都失败时，如何获得有效学习信号？
- **常见误区：** 把“没有人工过程标注”解释为“没有任何先验知识或训练数据”。

<a id="t07"></a>

### T07. GRPO 为什么能省去独立价值模型？组内相对优势有什么问题？

- **难度 / 适用岗位：** 高级；后训练、RL 系统。
- **原创作答要点：** 对同一提示采样 G 个回答，以组内奖励基线构造优势，例如 A_i=(r_i−mean(r))/(std(r)+ε)，配合策略比率截断与相应正则。[DeepSeekMath](https://arxiv.org/abs/2402.03300)提出 GRPO，核心思路是以组信息代替单独训练的 critic；不同实现的 KL 和归一化细节必须查代码。全同奖励组信号弱，标准差、题目难度及长度会影响梯度。省去 critic 不代表 rollout、参考策略或奖励计算免费。
- **深入追问：** 增大 group size 是否总比增加不同问题数好？如何做受控比较？
- **常见误区：** 认为 GRPO 就是普通监督交叉熵，或所有 GRPO 变体都有相同偏差。

<a id="t08"></a>

### T08. R1-Zero 与 R1 的训练差异，能支持哪些结论？

- **难度 / 适用岗位：** 中高级；后训练、研究。
- **原创作答要点：** [官方仓库](https://github.com/deepseek-ai/DeepSeek-R1)区分了从基座直接进行 RL 的 R1-Zero，以及加入冷启动数据和多阶段训练的 R1；同时说明 Zero 的可读性、语言混杂等问题。能够讨论“基座能力如何被 RL 调动”，不能推出从零随机初始化仅靠奖励就能获得全部知识。比较最终模型时，需要分离基础模型、数据、RL、蒸馏与采样预算的贡献。[论文](https://arxiv.org/abs/2501.12948)初版为 2025 年，页面现有 2026 年修订。
- **深入追问：** 如何验证冷启动改善的是输出规范还是可迁移的解题策略？
- **常见误区：** 将 R1-Zero 与 R1 混为一个训练流程，或把基座预训练成本排除后宣称训练几乎免费。

<a id="t09"></a>

### T09. 可验证奖励 RLVR 为什么仍会 reward hacking？

- **难度 / 适用岗位：** 高级；RL、评测、安全。
- **原创作答要点：** “可验证”描述的是某一奖励计算，不等于完整目标已被刻画。数学可能仅抽取最终数字，代码可能只覆盖有限测试，格式规则可能接受空洞模板。先威胁建模，再用隐藏测试、变形测试、执行隔离和奖励审计检验；检查正确率、测试覆盖率、异常输出和奖励分布。把验证器升级后的鲁棒性作为独立指标，避免模型只学会固定判题器的漏洞。
- **深入追问：** 如何区分模型发现合法新解法与钻验证器空子？
- **常见误区：** 奖励来自程序就视为不可欺骗，或偷偷用线上评测失败案例反复调参。

<a id="t10"></a>

### T10. 推理蒸馏要保留长轨迹还是只保留答案？怎样设计实验？

- **难度 / 适用岗位：** 高级；模型压缩、后训练。
- **原创作答要点：** 答案监督成本较低，但可能丢失中间计算模式；轨迹监督增加训练 token，也可能复制冗余和错误。固定学生基座、训练 token 与数据题目，比较答案、完整轨迹、精炼轨迹、不同教师与多样轨迹；保证题目级切分。筛选要检查终局与步骤，记录教师生成成本及授权。评估 pass@1、预算曲线和 OOD 任务，防止把记住教师措辞解释为策略迁移。
- **深入追问：** 学生上下文较短时，如何压缩轨迹同时保持可验证结构？
- **常见误区：** 只控制样本数不控制 token，或将蒸馏后的成功等同于学生独立学会教师全部能力。

<a id="t11"></a>

### T11. 固定推理预算下，应该增加深度、采样宽度还是模型大小？

- **难度 / 适用岗位：** 高级；推理算法、系统。
- **原创作答要点：** 深度用于单条轨迹展开与修正，宽度用于多个候选探索，更大模型改变单次能力和单 token 成本。[测试时计算研究](https://arxiv.org/abs/2408.03314)强调题目难度对策略收益的影响。应画正确率—总 FLOPs、延迟和费用的 Pareto 曲线；并行多样本可降低等待时间，却不降低总计算。路由器只能使用部署可获得的信号，不能通过标准答案预知题目难度。
- **深入追问：** 平均预算不变时，怎样给不同请求动态分配算力并控制 P95 延迟？
- **常见误区：** 只按输出 token 计费比较，却遗漏 prefill、验证器和并行资源占用。

<a id="t12"></a>

### T12. Tree of Thoughts 与直接生成长 CoT 的关键差异是什么？

- **难度 / 适用岗位：** 中高级；搜索、Agent、推理算法。
- **原创作答要点：** [ToT](https://arxiv.org/abs/2305.10601)把文本中间状态作为可搜索节点，需明确状态表示、候选生成、状态评价、搜索策略和终止条件。收益来自保留分支、前瞻及回溯，不只是提示中写“树状思考”。实现时限制分支数与重复状态，用可验证约束剪枝；比较相同计算预算下的随机采样和顺序修正，避免把更多调用误算为搜索策略优势。
- **深入追问：** 评估器偏向表面漂亮但错误的状态时，搜索会如何放大错误？
- **常见误区：** 把任意多 Agent 对话都称为 ToT，或不计算搜索节点扩张成本。

<a id="t13"></a>

### T13. 推理长度增加不再涨分，如何诊断 overthinking？

- **难度 / 适用岗位：** 中高级；推理优化、后训练。
- **原创作答要点：** 记录首次正确答案出现位置、反复改答、重复段落、截断比例和分题型收益；区分模型自主选择长回答与人为分配长预算。通过随机预算或同题配对干预分析因果关系，不能仅看“长回答更难”的相关性。[s1](https://arxiv.org/abs/2501.19393)展示了 budget forcing，可作为实验起点；强制续写是否有效需要按任务重测。提前停止必须兼顾错误自信与输出完整性。
- **深入追问：** 如何训练一个不依赖标准答案的停止器？
- **常见误区：** 把延长思考视为单调有效，或从长度与错误率相关直接得出长推理导致错误。

<a id="t14"></a>

### T14. “请检查并修正答案”为什么可能没有效果？

- **难度 / 适用岗位：** 中级；Agent、应用算法。
- **原创作答要点：** 若修正阶段没有新证据、可执行反馈或独立判断，同一模型可能重复初始偏差，也可能把正确答案改错。比较无反馈重写、模型自评、独立裁判、外部执行结果四组；统计错→对、对→错和净收益。对工具反馈先确认可靠性与权限，再让模型定位具体违反的约束，而非笼统要求“更认真”。保留原答案用于审计和回退。
- **深入追问：** 怎样防止模型为了通过错误的外部反馈而改坏正确解？
- **常见误区：** 把二次调用的提升全部归因于“反思能力”，忽略第二次采样和额外预算。

<a id="t15"></a>

### T15. 如何设计工具增强推理，避免“会调用 Python”成为新的脆弱点？

- **难度 / 适用岗位：** 高级；Agent、工具学习。
- **原创作答要点：** 模型负责问题形式化、选择工具和解释结果；执行器负责确定性计算，二者都可能出错。对单位、符号假设、输入范围和工具返回结构做校验，隔离执行并限制资源；工具错误应作为显式状态。做“正确形式化但计算错”“形式化错但执行成功”等分层评测。比较纯文本、工具可用但不强制、强制工具三个条件，报告工具调用成本和失效恢复。
- **深入追问：** 计算器给出精确数字，为什么结论仍可能错误？
- **常见误区：** 认为工具执行成功就证明题意建模正确，或把工具返回内容当作更高优先级指令。

<a id="t16"></a>

### T16. Lean 等形式化验证能否保证模型给出的数学结论正确？

- **难度 / 适用岗位：** 高级；数学推理、形式化方法。
- **原创作答要点：** 在给定逻辑、假设与可信内核下，证明检查可确认形式化命题的可推导性；仍要验证自然语言问题是否被忠实翻译、假设是否过强、是否留下未证明占位。将任务拆为命题形式化、证明搜索、内核检查与非形式化解释。评估时禁止跳过证明的机制，固定库版本和可用引理；区分证明存在率与在预算内找到证明的概率。
- **深入追问：** 形式化成“如果结论成立，则结论成立”，为什么会通过但没有价值？
- **常见误区：** 把检查器接受误读命题的证明，当成原问题已经被解决。

<a id="t17"></a>

### T17. 可读的思维链是否是可靠解释？如何研究 faithfulness？

- **难度 / 适用岗位：** 高级；可解释性、对齐、研究。
- **原创作答要点：** 正确性回答“结果是否对”，忠实性回答“解释是否反映影响输出的真实因素”。[CoT 忠实性研究](https://arxiv.org/abs/2305.04388)展示了未被解释承认的输入偏置信号。可设计选项顺序、无关提示、关键步骤替换等干预，观察答案与解释是否同步变化；注意干预也可能制造分布漂移。对用户提供可核验依据和简洁论证，避免将内部文字叙述当作因果证明。
- **深入追问：** 模型输出的理由始终正确，能否据此证明它依赖这些理由作答？
- **常见误区：** 把解释漂亮等同于可信，或由部分不忠实案例推出所有中间文本都无用。

<a id="t18"></a>

### T18. 读一篇 2026 推理技术报告，你会如何设计复现实验与反证？

- **难度 / 适用岗位：** 研究级；研究员、技术负责人。
- **原创作答要点：** 以 [LongCat-Flash-Thinking-2601](https://arxiv.org/abs/2601.16725)为阅读案例：报告讨论多环境训练、噪声鲁棒性及扩展深度与宽度的 Heavy Thinking。复现应分别检验这些组件；固定基础能力与资源，设置未见环境、工具接口变更、噪声强度和失败恢复测试。报告自述领先不能替代独立重跑，更不能代表 2026-10-22 全市场排名。先列可证伪假设、预算、基线与置信区间，再决定要复现多少组件。
- **深入追问：** 只有最终权重，没有全部环境和数据时，哪些结论可验证，哪些只能视为作者主张？
- **常见误区：** 从技术报告的组合系统结果推断某个单一算法必然有效。
