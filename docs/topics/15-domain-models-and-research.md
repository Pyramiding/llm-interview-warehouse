# 15. 领域模型、推荐搜索、AI for Science 与研究设计

> **题目性质：原创研究延伸题，不是企业真题。** 面向垂直领域算法、推荐搜索、研究员及博士实习岗位。核查截止 **2026-10-22**。医学、金融和法律相关内容只讨论模型研究与系统设计，不构成诊断、投资或法律建议；离线学术成绩不能替代相应场景的专业验证。文中实验建议与判断框架是编者原创整理。

<a id="x01"></a>

### X01. 一个垂直领域任务，何时选提示、RAG、SFT、继续预训练或从头训练？

- **难度 / 适用岗位：** 中高级；领域算法、技术负责人。
- **原创作答要点：** 先定位差距：知识时效与出处可优先检索，行为格式与工作流可用 SFT，术语分布和表征适配可研究继续预训练；从头训练要有足够数据、算力和可证实收益。建立通用强基线，统一成本与业务验收，按增量收益选择。数据少时复杂训练容易过拟合；RAG、SFT 与继续预训练也可组合，不能按流行程度选方法。
- **深入追问：** 模型知道领域知识却总是不按格式答，继续预训练是否是第一选择？
- **常见误区：** 认为专业名词多就必须训练一个全新大模型，或把 RAG 当成万能知识保证。

<a id="x02"></a>

### X02. 领域数据与通用数据如何混合，才能兼顾专业性与泛化？

- **难度 / 适用岗位：** 高级；预训练、领域模型。
- **原创作答要点：** [BloombergGPT](https://arxiv.org/abs/2303.17564)是混合金融与通用数据训练的研究案例；具体配比不能照搬到新领域。固定总 token、模型与评测，比较不同混合比例、采样温度和训练阶段，跟踪领域收益与一般能力回归。数据应按质量、时效、许可、重复与覆盖分层；专业文本中的模板噪声和错误也会被放大。以任务价值而非困惑度单独决定最终方案。
- **深入追问：** 领域 perplexity 降低，但专业问答不涨分，可能为什么？
- **常见误区：** 领域数据越纯越好，或把一个领域的最佳配比称为通用经验定律。

<a id="x03"></a>

### X03. 专业术语、数字、单位和符号怎样影响模型适配？

- **难度 / 适用岗位：** 中高级；领域 NLP、数据工程。
- **原创作答要点：** 先测 tokenizer 的术语碎片化、序列膨胀与符号覆盖，不能只看词表大小。扩词涉及 embedding 初始化、旧 token 兼容与训练稳定性；若基座已能表达，标准化与任务数据可能更划算。数字与单位用结构化字段、工具计算和一致性检查辅助，保留原始证据避免过度归一化破坏含义。评测需包含近义术语、缩写歧义、量纲和范围变化。
- **深入追问：** 同一缩写在两类业务含义不同，如何让模型利用上下文而非硬编码？
- **常见误区：** 把新增领域词表当作获得领域知识，或将精确数字计算完全交给语言生成。

<a id="x04"></a>

### X04. LLM 如何用于推荐？生成语义 ID 与生成自然语言推荐有何不同？

- **难度 / 适用岗位：** 高级；推荐算法、生成式检索。
- **原创作答要点：** 自然语言推荐主要输出描述或理由，候选合法性与排序仍需控制；语义 ID 路线将物品编码为离散序列并生成候选。[Recommender Systems with Generative Retrieval](https://arxiv.org/abs/2305.05065)使用语义 codeword 表示物品，可作为 TIGER 路线入口。要讨论 ID 冲突、可解码性、新物品更新、冷启动与生成约束；语义接近未必等于用户偏好接近，仍需行为数据验证。
- **深入追问：** 模型生成一个不存在的商品 ID，如何在解码与系统层处理？
- **常见误区：** 推荐理由好听就视为排序更好，或把文本生成合法性等同于候选命中率。

<a id="x05"></a>

### X05. 生成式检索与双塔向量检索、倒排检索有什么根本差异？

- **难度 / 适用岗位：** 高级；搜索、推荐研究。
- **原创作答要点：** 倒排与双塔通常显式维护索引并检索候选；生成式检索直接解码文档或物品标识。[DSI](https://arxiv.org/abs/2202.06991)是必要经典。比较表达能力时也要测文档增删、知识更新、召回多样性、受限解码成本和故障恢复；不能只比较静态数据集上的命中率。常见工程方案可将生成、检索和重排组合，按吞吐与新鲜度需求选择。
- **深入追问：** 每小时新增大量商品时，生成式 ID 模型如何适配？
- **常见误区：** 参数中含有语料知识就等于具备随时更新的完整搜索索引。

<a id="x06"></a>

### X06. 推荐系统接入大模型后，如何避免离线涨分、线上无收益？

- **难度 / 适用岗位：** 高级；推荐评测、应用算法。
- **原创作答要点：** 采用按时间和用户行为切分，防止未来互动、商品属性或评价泄漏。离线看 Recall / NDCG、覆盖与长尾，但曝光与位置偏差会影响解释；线上以授权的小范围实验验证，并监控延迟、业务质量与用户负担。记录候选全集与过滤规则，避免不同模型使用不同可选商品。LLM 可能改善语义理解，也可能过度推荐热门商品和同质内容。
- **深入追问：** 新方案提升点击率但降低长期留存，应如何设计后续实验？
- **常见误区：** 只在固定少量负样本上排名高，就声称全库检索或真实用户体验更好。

<a id="x07"></a>

### X07. 搜索中的 query rewrite、rerank 与答案生成应如何分别评估？

- **难度 / 适用岗位：** 中高级；搜索、RAG。
- **原创作答要点：** 改写改变召回入口，要保留用户约束，检查实体、否定和时间是否被改坏；重排只在候选中重新排序，无法挽救未召回证据；答案生成要检查主张与引用。设置原始 query、人工改写、oracle 候选等对照定位瓶颈。多轮查询要记录前后依赖，处理歧义而非擅自补充意图；时效信息应通过当前可追溯来源核验。
- **深入追问：** 改写召回率上升，但用户关键约束被删除，应该怎样计分？
- **常见误区：** 用最终答案分数归因某个上游组件，或默认更长改写总更好。

<a id="x08"></a>

### X08. 医学考试高分能否说明模型可以用于临床诊疗？

- **难度 / 适用岗位：** 高级；医疗 AI、可信模型。
- **原创作答要点：** 不能。考试问答与临床流程在信息缺失、时间压力、患者分布、错误后果和责任边界上不同。[Med-PaLM 2](https://arxiv.org/abs/2305.09617)研究医学问答并进行多维人工评价，是能力研究证据，不是通用临床许可。研究设计应分别评估证据时效、严重错误、表达不确定性、转交专业人员与真实工作流影响；开展实际应用需领域专家、机构流程及适用要求确认。
- **深入追问：** 模型给出总体正确但遗漏关键危险信息的回答，怎样计入评价？
- **常见误区：** 把通过考试等同于获得执业资格，或仅按平均准确率评价医疗风险。

<a id="x09"></a>

### X09. 医疗领域继续预训练，应怎样组织证据、数据隐私与跨机构验证？

- **难度 / 适用岗位：** 高级；医疗模型、数据治理。
- **原创作答要点：** [MEDITRON](https://arxiv.org/abs/2311.16079)使用医学语料与指南适配基座，可用于讨论数据策展。不同指南、地区和年份可能冲突，需保留证据来源、适用范围与更新日期。患者级、机构级和时间级切分比随机拆文本更有意义；采用经授权的去标识数据，控制检索、日志与训练的暴露面。基准提升与临床收益分开验证，不能让模型自行裁决高风险诊疗。
- **深入追问：** 同一患者多次就诊记录跨训练测试集合，会带来什么偏差？
- **常见误区：** “公开医学论文”自动代表正确且适合所有患者，或去掉姓名就认为已消除再识别风险。

<a id="x10"></a>

### X10. 金融大模型怎样处理时间、精确数字与决策风险？

- **难度 / 适用岗位：** 高级；金融 NLP、领域评测。
- **原创作答要点：** [BloombergGPT](https://arxiv.org/abs/2303.17564)讨论金融语言任务，不应据此承诺投资回报。评估必须按当时可获得的信息设置时间截面，防止用后来的公告、复权数据或标签解释过去；数字计算使用可审计工具，单位、币种、报告期与来源逐一对应。把信息抽取、研究辅助与真实交易决策区分，保留人工复核及组织风控约束，输出不能作收益保证。
- **深入追问：** 年报发布时间晚于所预测的股价区间，如何影响回测可信度？
- **常见误区：** 情感分类提升就推断可赚钱，或在金融问题中忽略信息发布时间。

<a id="x11"></a>

### X11. 法律、企业制度等规则密集领域，如何处理版本与适用范围？

- **难度 / 适用岗位：** 中高级；法律科技、企业知识助手。
- **原创作答要点：** 将文档实体、颁布与生效时间、地区、层级、修订状态和适用对象作为结构化信息。检索先过滤权限与适用范围，再进行版本对照和引用支持检查；冲突时暴露差异并转交有权限的专业人员。模型可辅助查找与整理，不应伪造具体条款、判例或声称当前合规。测试旧版制度、例外条款、附件优先级和信息不足情形。
- **深入追问：** 两份同名制度均来自官方目录，但生效时间不同，如何回答历史事件？
- **常见误区：** 把检索到的第一段当成当前有效规则，或忽略来源权限与地域限制。

<a id="x12"></a>

### X12. AI for Science 都是“大语言模型”吗？AlphaFold 类方法与 LLM 科研助手有何不同？

- **难度 / 适用岗位：** 中高级；AI for Science、研究。
- **原创作答要点：** AI for Science 包含结构预测、分子生成、物理模拟、符号搜索与研究流程辅助；不是所有模型都以文本 next-token 训练。AlphaFold 3 是生物分子结构建模系统，不应简单称为聊天 LLM。其 [论文](https://www.nature.com/articles/s41586-024-07487-w)和 [官方仓库](https://github.com/google-deepmind/alphafold3)可用于界定任务；仓库明确输出为理论预测，不能用于临床。结构置信度、实验条件与实验验证都影响结论。
- **深入追问：** 模型预测了高置信结构，是否足以证明某分子具有预期生物功能？
- **常见误区：** 把准确结构、结合效应、功能结果和临床疗效当成同一件事。

<a id="x13"></a>

### X13. FunSearch 类“生成候选 + 可执行评价”与让模型直接回答有什么不同？

- **难度 / 适用岗位：** 高级；程序搜索、数学与科学 AI。
- **原创作答要点：** 系统利用生成模型提出程序或构造，再通过外部评价函数筛选并迭代；模型生成的是候选，外部验算提供约束。[FunSearch 官方仓库](https://github.com/google-deepmind/funsearch)包含已发现构造和评测示例，也明确并未提供全部模型与分布式运行基础设施。研究要固定评价函数，防止候选投机利用漏洞；将找到新构造、发现经验规律和完成一般性证明区分。
- **深入追问：** 当评价函数仅覆盖有限输入时，如何避免发现的是测试集特解？
- **常见误区：** 将模型提出的想法直接视为科学发现，或把代码公开误解为完整实验栈可复现。

<a id="x14"></a>

### X14. 自动科研 Agent 的“生成论文”与“产生可靠新知识”差在哪里？

- **难度 / 适用岗位：** 研究级；科学 Agent、研究员。
- **原创作答要点：** [The AI Scientist（2024）](https://arxiv.org/abs/2408.06292)组织想法、实验、写作与自动评审流程；[2026 年后续论文](https://www.nature.com/articles/s41586-026-10265-5)延续端到端研究议题。应独立核验代码、数据、统计、引用和新颖性，避免生成器与裁判共同偏差；公开失败结果及人工干预。自动评审分数、文章形式完整和真实外部学术认可属于不同证据，运行研究代码需隔离环境与资源上限。
- **深入追问：** 自动评审给高分但独立复现实验失败，应如何判断系统能力？
- **常见误区：** 论文能生成、能自评通过，就认定发现已被独立确认。

<a id="x15"></a>

### X15. 面试官让你提出一个大模型研究方向，怎样避免只有口号？

- **难度 / 适用岗位：** 研究级；研究员、博士实习。
- **原创作答要点：** 用“现象—证据—机制假设—干预—可证伪预测”表达。例如怀疑长推理收益来自重复采样，就设计固定 token 预算、相同题目、不同串并行策略的比较。界定目标分布、模型规模、数据和预算，明确基线、主指标、失败标准及预期局限。先做最小诊断实验决定是否扩大；价值来自解决可验证问题，而非叠加多个热门模块。
- **深入追问：** 实验只发现一个负结果，怎样判断它仍有研究价值？
- **常见误区：** “做一个更强的 Agent”即研究问题，或只提出预期成功结果而无可反驳条件。

<a id="x16"></a>

### X16. 怎样设计消融，使提升真的能归因于你提出的模块？

- **难度 / 适用岗位：** 高级；算法研究。
- **原创作答要点：** 固定数据、训练 token、算力、超参搜索预算与推理成本；用功能匹配基线，避免新模块增加参数和数据后仍称公平。单因素消融能定位局部作用，模块交互需要组合实验。合成数据要记录教师、提示、筛选和失败样本，按题目家族划分。报告方差与各切片表现，检查收益是否来自模板、长度或验证器偏置，而非期望机制。
- **深入追问：** 去掉模块后训练不稳定，怎样区分模块功能与超参不适配？
- **常见误区：** 给完整模型充分调参、给消融模型随便跑一次，再把差距全算创新收益。

<a id="x17"></a>

### X17. 复现一篇论文时，哪些证据应保存，哪些主张不能轻易接受？

- **难度 / 适用岗位：** 中高级；研究工程、研究员。
- **原创作答要点：** 保存论文版本、代码 commit、模型权重标识、数据哈希、配置、随机种子、环境与评测输出。先复现关键主张，再测试更广泛推广；将无法获得的数据、计算差距和实现猜测单列，不能用猜测填补作者方法。若结果不符，检查评分、预处理、模板和资源，再报告误差范围。固定快照比引用可变的 main 分支更适合长期追踪。
- **深入追问：** 只能复现趋势，不能复现绝对数字，怎样准确写结论？
- **常见误区：** 运行官方示例成功等于复现论文，或复现失败就直接断言原论文造假。

<a id="x18"></a>

### X18. 如何在研究面试中讲清自己的项目，并诚实划分个人贡献？

- **难度 / 适用岗位：** 全级别；算法与研究岗位。
- **原创作答要点：** 准备 3 分钟与 15 分钟两版：问题与约束、最强基线、关键设计、自己的实质工作、验证结果和失败教训。用具体对照说明改动为何有效，区分独立完成、团队协作和复用开源；未做的实验直接标为待验证。能回答预算、数据来源、误差类型、上线或复现限制，并提出下一步最有信息价值的实验，比堆砌模型名称更有说服力。
- **深入追问：** 如果删除你负责的部分，项目结果会怎样变化？有什么证据？
- **常见误区：** 将团队成果都算个人贡献，或用论文结论代替自己实际做过的验证。
