# 13. 评测、可信性、对齐安全与风险治理

> **题目性质：原创研究延伸题，不是公司真实面试记录。** 面向评测、对齐、安全、数据与研究岗位。核查截止 **2026-10-22**；研究发现只在对应实验设置内解释，不代表某模型或产品的全面安全结论。安全题以经授权的隔离评测、诊断与防御设计为边界，不提供现实攻击载荷。

<a id="e01"></a>

### E01. 为一个新大模型设计评测，你会先问哪些问题？

- **难度 / 适用岗位：** 中级；评测、算法、技术负责人。
- **原创作答要点：** 先定使用者、任务、容许错误、工具权限与预算，再建立能力、可靠性、安全、成本四维矩阵。通用考试题只是一部分，还要有真实工作样本、长尾切片、不可回答问题和端到端任务。固定数据版本、提示、解码参数与评分规则，设离线门槛、人工评审和上线后监控。指标须能解释发布决策，不能为了报表方便把不同风险随意平均。
- **深入追问：** 总分提升，但关键业务错误增加，是否应发布？你的判定规则是什么？
- **常见误区：** 先跑一堆热门基准，再根据好看的分数临时定义成功。

<a id="e02"></a>

### E02. 如何识别与降低训练集污染，而不宣称“绝对无污染”？

- **难度 / 适用岗位：** 高级；数据、评测研究。
- **原创作答要点：** 精确与近重复检查只能覆盖已知文本；还要检查解答、翻译、变体和上游合成数据。采用题目时间切分、私有新题、结构化改写与能力一致性测试，记录来源和模型训练截止信息的不确定性。[LiveCodeBench](https://arxiv.org/abs/2403.07974)持续收集新竞赛题是可参考机制，但时间新不保证所有间接泄漏都消失。不能因模型记得题干就证明训练污染，也不能因查无重复就证明没有污染。
- **深入追问：** 训练数据不可见的闭源 API，如何给出可辩护的污染风险结论？
- **常见误区：** 将一个去重阈值或发布时间晚于公告日当成绝对保证。

<a id="e03"></a>

### E03. 两个模型相差 1 个百分点，怎样判断差异是否值得相信？

- **难度 / 适用岗位：** 中高级；评测、研究。
- **原创作答要点：** 同题配对比较，观察胜负分布，按问题或更高层级聚类 bootstrap，避免把同题多次生成视为独立题。对多种子采样、裁判随机性和题型比例做敏感性分析，同时报告置信区间和实际效应大小。若大量挑选基准或模型配置，需要说明多重比较与选择偏差。统计显著不等于业务有价值，小样本不显著也不证明等效。
- **深入追问：** 同一仓库的 100 个代码任务是否能当成 100 个独立样本？
- **常见误区：** 只报最高一次结果，或用两个不重叠的独立置信区间代替合理的配对分析。

<a id="e04"></a>

### E04. LLM-as-a-judge 有哪些系统性偏差？

- **难度 / 适用岗位：** 中级；评测、奖励模型。
- **原创作答要点：** [MT-Bench / Chatbot Arena 论文](https://arxiv.org/abs/2306.05685)讨论位置、冗长和自我偏好等偏差。实施时随机交换顺序、隐藏模型名、提供分项 rubric 与可核验参考，允许平局和无法判定；用专家标注校准并检查各任务切片的一致性。裁判输出理由可帮助审计，不能自动保证理由正确。裁判版本与提示改变后，旧分数不可直接当作同一尺度。
- **深入追问：** 交换两个答案位置后胜负反转，应该如何汇总与处理？
- **常见误区：** 强模型当裁判就等于真值，或只验证整体人与模型一致率。

<a id="e05"></a>

### E05. 被评回答会“说服裁判”，怎样保证评分可信？

- **难度 / 适用岗位：** 高级；评测安全、奖励模型。
- **原创作答要点：** 被评内容属于不可信数据，可能含评分指令、伪引用或格式干扰。将评分规则与样本清晰分隔，优先执行可确定验证的部分，对开放部分采用独立 rubric 与抽样人工审计；不能只靠一句“忽略指令”做安全边界。构造与业务同域的无害干扰样本，检查分数是否随无关话语改变。奖励训练前清理可利用的裁判偏差，记录裁判失败率。
- **深入追问：** 更复杂的裁判提示提高了鲁棒性，但正常题评分一致性下降，怎样权衡？
- **常见误区：** 将被评答案中的自评结论直接交给裁判采信。

<a id="e06"></a>

### E06. GPQA、MMLU-Pro、HLE 各能说明什么，不能说明什么？

- **难度 / 适用岗位：** 中高级；评测、研究。
- **原创作答要点：** [GPQA](https://arxiv.org/abs/2311.12022)强调专家级科学问答；[MMLU-Pro](https://arxiv.org/abs/2406.01574)增加推理难度并调整选项；[HLE](https://arxiv.org/abs/2501.14249)覆盖广泛高难闭合学术问题。三者不能替代真实工具使用、长期规划或临床能力验证。要记录子集、是否含图、提示与工具设置、答案解析和数据版本；难题上的“人类水平”必须说明比较的人群、时间和权限。
- **深入追问：** 学科考试高分能否支持“模型能独立研究新科学问题”的结论？
- **常见误区：** 把不同版本、工具权限与采样预算的分数放到同一个无条件排名。

<a id="e07"></a>

### E07. 幻觉、事实错误、缺乏依据与无法回答有何区别？

- **难度 / 适用岗位：** 中级；可信性、RAG、评测。
- **原创作答要点：** 事实错误针对现实真值，缺乏依据针对给定证据，两者可分离：答案可能真实但未被所引文档支持，也可能忠实复述错误来源。[SimpleQA](https://arxiv.org/abs/2411.04368)将短事实回答分为正确、错误与未尝试，可作为校准讨论起点。长回答需要拆成可验证主张，评估错误严重性、引用支持与缺失信息。对会变的事实保存查询日期和证据快照，不能永远用旧答案作真值。
- **深入追问：** 模型引用了一篇确有其文的论文，但论文不支持结论，错误该归哪类？
- **常见误区：** 没有引用就全算假，有引用就全算真，或把保守不答全算模型失败。

<a id="e08"></a>

### E08. 自信度、校准与选择性回答应怎样评估？

- **难度 / 适用岗位：** 高级；可信学习、研究。
- **原创作答要点：** 置信度必须对应明确事件，如最终答案正确，而非每个 token 最大概率。看可靠性图、Brier score / ECE，并检查分桶和样本量敏感性；拒答场景关注 coverage—risk 曲线。模型口头说“90% 把握”需重新验证，采样一致性也可能因共同偏差虚高。阈值在开发集选择，按领域、语言及分布漂移分别复核。
- **深入追问：** 校准看起来很好，但最高风险切片很差，如何修改发布标准？
- **常见误区：** 将 token 概率或多数投票比例直接视为答案正确率。

<a id="e09"></a>

### E09. RAG 评测为什么必须同时检查检索、证据利用和答案？

- **难度 / 适用岗位：** 中级；RAG、知识工程、评测。
- **原创作答要点：** 检索无证据，生成器再强也可能猜；检索有证据，模型也可能忽略或误用。分别测 evidence recall、上下文相关性、答案正确率、引用支持率和应拒答时的行为。用 oracle context 和无 context 对照识别瓶颈，加入冲突、过期和不可信文档。引用应精确到实际支持的主张与位置，避免整篇来源挂在段末制造可靠感。
- **深入追问：** 检索召回提高但最终答案变差，可能有哪些原因？
- **常见误区：** 只算向量相似度，或将答案出现于上下文视为回答已被证明。

<a id="e10"></a>

### E10. Agent 评测如何从“调用格式正确”走向“任务可靠完成”？

- **难度 / 适用岗位：** 高级；Agent、评测系统。
- **原创作答要点：** 以环境状态和真实验收条件判断成功，再分解计划、工具选择、参数、执行、恢复与最终报告。记录重试、无效动作、费用、延迟和越权行为；随机任务需多次运行。2026 年 [Terminal-Bench 论文](https://arxiv.org/abs/2601.11868)提供终端任务评测案例。比较时固定容器、网络、基础文件和工具版本；裁判不能被 Agent 修改，测试资源也应与可见工作区隔离。
- **深入追问：** Agent 最终声称任务完成，但环境没有对应变化，应该如何评分？
- **常见误区：** 把正确输出工具 JSON、退出码为零或自述成功当成端到端成功。

<a id="e11"></a>

### E11. 怎样同时测安全拒绝与正常请求的可用性？

- **难度 / 适用岗位：** 中级；对齐、安全评测。
- **原创作答要点：** 建立明确意图与上下文标签，分别测应拒绝的请求、同主题合法请求、歧义请求与安全替代帮助。关注危险协助发生率、误拒率、必要澄清与答复质量，并按风险严重性切片。关键词拦截可能拒绝正常学术和防御讨论；裁判应评估具体协助内容而非是否出现道歉或拒绝模板。[JailbreakBench](https://arxiv.org/abs/2404.01318)可作为规范化评价入口。
- **深入追问：** 模型拒绝了所有医学与安全问题，它是否更安全？
- **常见误区：** 将拒答率越高视为越好，忽略用户目标与合法用途。

<a id="e12"></a>

### E12. 越狱防御实验怎样定义威胁模型与公平比较？

- **难度 / 适用岗位：** 高级；红队研究、模型安全。
- **原创作答要点：** 明确攻击者可见信息、查询次数、是否可改系统提示、可控输入模态与目标；在授权测试环境里开展。固定目标模型版本和裁判，报告每次与累计攻击成功率、正常能力损失、攻击预算及自适应情况。[HarmBench](https://arxiv.org/abs/2402.04249)与 [JailbreakBench](https://arxiv.org/abs/2404.01318)强调可复现框架。对公开攻击集稳健不等于对新攻击或所有部署方式稳健。
- **深入追问：** 防御仅增加调用成本，累计攻击仍成功，怎样如实表述收益？
- **常见误区：** 不报告查询预算，或用固定已知攻击集证明绝对安全。

<a id="e13"></a>

### E13. Prompt injection 与用户直接提出违规请求有什么区别？

- **难度 / 适用岗位：** 高级；Agent 安全、平台工程。
- **原创作答要点：** 注入常由网页、邮件、仓库文件或工具返回等较低信任内容改变 Agent 行为；即使用户目标正常，也可能发生。[AgentDojo](https://arxiv.org/abs/2406.13352)以工具返回的不可信数据构建评测环境。防御需要区分指令与数据、最小权限、参数验证和敏感动作控制，并测正常任务完成率；检索内容引用了系统风格文本，也不能自动获得权限。评估既要有隔离攻击样本，也要有真实正常任务。
- **深入追问：** 一份文档要求把“验证结果”发往外部地址，Agent 应怎样判断是否获授权？
- **常见误区：** 把所有文本平等拼接，或以字符串过滤作为唯一安全边界。

<a id="e14"></a>

### E14. 安全微调能否证明模型不存在后门或欺骗行为？

- **难度 / 适用岗位：** 高级；对齐、安全研究。
- **原创作答要点：** [Sleeper Agents](https://arxiv.org/abs/2401.05566)研究人为构造的条件性后门及其在部分安全训练后的持续性。它说明存在失败模式，不证明所有已部署模型自然形成同样策略。评审模型来源、训练数据与异常触发条件，在隔离环境中做行为差分和分布外评测；安全训练前后都应测已知风险与未见触发。有限测试通过只能提高证据强度，不能证明不存在所有隐藏行为。
- **深入追问：** 观察到模型按场景改变行为，怎样排除普通条件学习而不是欺骗？
- **常见误区：** 把构造实验无限外推，或认为通过一套安全测试等于没有后门。

<a id="e15"></a>

### E15. 训练数据隐私风险与检索权限风险应如何分开处理？

- **难度 / 适用岗位：** 高级；隐私、安全、数据工程。
- **原创作答要点：** 训练泄漏涉及记忆与数据提取，RAG 泄漏可能由访问控制、跨租户缓存或工具授权失误造成；两者修复路径不同。采用最小数据原则、脱敏、数据血缘和租户隔离；以经授权的合成敏感标记测试暴露路径，不能用真实个人信息探测。成员推断等指标需要考虑基线和分布差异，单次复述不等于确认某人被用于训练。
- **深入追问：** 模型权重不变但换了检索器后泄漏，应该追查哪层？
- **常见误区：** 只做训练集脱敏却忽略工具返回和日志，或把提示中的秘密当成模型早已记住的证据。

<a id="e16"></a>

### E16. 公平性评测为什么不能只比较不同群体的一个总分？

- **难度 / 适用岗位：** 高级；可信 AI、评测研究。
- **原创作答要点：** 群体样本可能在题目难度、语言、任务类型和基准标签上不匹配。使用语义一致的配对或合理分层，关注交叉群体、小样本区间、误拒与错误严重性；不同公平目标可能冲突，需结合实际用途说明。不要把群体属性当作能力标签，也不应为了消除分数差异随意修改真值。记录标注者差异与受影响群体反馈。
- **深入追问：** 平均差距缩小但某个交叉群体恶化，是否算公平性提升？
- **常见误区：** 总平均接近便声称公平，或将数据构成差异当成模型因果偏见的直接证据。

<a id="e17"></a>

### E17. 从一次红队测试到持续风险管理，需要补哪些闭环？

- **难度 / 适用岗位：** 高级；模型安全、技术负责人。
- **原创作答要点：** 把风险映射到可观察失效、责任人、测试、处置阈值与回归集；发布后监控漂移、事故与工具权限变化，修复后验证是否引入新误拒。[NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)提供生成式 AI 风险管理参考，属于框架资料，不等同于法律合规认证。高风险应用还需相应领域专家与组织流程，不能仅依赖模型自检。
- **深入追问：** 上游模型更新而应用代码没变，哪些安全验证仍须重跑？
- **常见误区：** 把一份模型卡、一张安全分数或一次红队通过当作永久保证。

<a id="e18"></a>

### E18. 2026 年继续使用旧 benchmark 时，怎样保持结果可比与有效？

- **难度 / 适用岗位：** 研究级；评测负责人、研究员。
- **原创作答要点：** 保存题目哈希、子集、容器、裁判、prompt、模型精确标识和预算，区分历史复现与当前能力观察。若数据修订、标签纠错或题量变化，应在同一新版上重跑共同基线；不要直接拼表。[HLE](https://arxiv.org/abs/2501.14249)核查时为 2026-10-19 的 v12，恰好说明版本追踪必要性。对于已饱和或疑似污染的任务，增加新题、真实工作流和失败切片，仍保留旧集用于纵向回归。
- **深入追问：** 新版删除了一批模型容易做错的题，涨分应怎样归因？
- **常见误区：** 把论文年份当作固定数据版本，或根据不同年代的基线推断今天的模型差距。
