# 14. 代码模型、软件 Agent 与具身 VLA

> **题目性质：原创研究延伸题，不是企业真题。** 前半部分覆盖代码训练与软件工程 Agent，后半部分覆盖视觉语言动作模型和机器人学习。核查截止 **2026-10-22**，覆盖 2023—2026。所有机器人实验建议应在经授权、具备独立安全控制的环境中实施；研究模型输出不能直接替代实际系统的安全约束。

<a id="b01"></a>

### B01. 代码模型与通用语言模型的训练差异在哪里？

- **难度 / 适用岗位：** 中级；代码模型、数据算法。
- **原创作答要点：** 代码包含严格语法、长程符号依赖、执行语义和多文件结构；训练数据还可能包含文档、issue、补丁与测试。[Code Llama](https://arxiv.org/abs/2308.12950)是理解代码专门化与补全任务的起点。应讨论语言配比、质量过滤、许可证、仓库重复和安全样本，评估函数生成、修复、理解与真实仓库任务。会写代码不自动等于理解需求、使用工具或维护项目。
- **深入追问：** 代码数据比例提高后，如何判断一般语言能力是否退化？
- **常见误区：** 所有可公开浏览的代码都可任意训练和再分发，或只看一种编程语言的函数题。

<a id="b02"></a>

### B02. Fill-in-the-Middle 如何构造？与普通续写目标冲突吗？

- **难度 / 适用岗位：** 中级；预训练、代码补全。
- **原创作答要点：** 将样本切成前缀、中间、后缀，用特殊标记重排，让模型根据两侧上下文生成中间片段；训练仍可用因果语言建模，但序列表示改变。需说明切分粒度、比例、特殊 token、混合续写数据和推理停止条件。比较标识符补全、函数体填充与跨块编辑，检查切分是否经常破坏语法。FIM 不提供自动多文件修改能力。
- **深入追问：** 缺失块含未闭合括号时，目标边界与 tokenizer 选择会怎样影响补全？
- **常见误区：** 把 FIM 当成双向 attention 的同义词，或忽视训练与推理模板一致性。

<a id="b03"></a>

### B03. 为什么通过单元测试不等于程序正确？怎样评测代码生成？

- **难度 / 适用岗位：** 中级；代码模型、评测。
- **原创作答要点：** 有限测试只约束有限输入；补充边界值、性质测试、变形测试、复杂度与安全检查，必要时使用形式化约束。报告 pass@1 / pass@k、编译率、执行超时和测试覆盖；未通过要区分环境错、语法错、算法错与需求误读。[LiveCodeBench](https://arxiv.org/abs/2403.07974)还覆盖修复、执行和测试输出预测，提醒评价能力不要限于一次生成。
- **深入追问：** 模型针对可见样例写了特判，哪些测试能揭示问题？
- **常见误区：** 只验证训练或提示中可见的测试，或把 pass@k 当作部署中单次成功率。

<a id="b04"></a>

### B04. 代码数据如何去重、切分并处理仓库级泄漏？

- **难度 / 适用岗位：** 高级；数据工程、代码研究。
- **原创作答要点：** 需处理 fork、镜像、拷贝文件、模板和生成代码，不能只逐行去重。仓库或项目家族级切分可降低相近代码跨集合泄漏，时间切分还需检查补丁与 issue 互相泄漏。[StarCoder2 / The Stack v2](https://arxiv.org/abs/2402.19173)是数据来源与代码模型研究入口。保存来源、许可证和移除记录；标识符重命名后的结构重复也需考虑，过滤规则不能只惩罚小众语言。
- **深入追问：** 同一库多个历史版本分别进入训练和测试，应怎样判定任务是否仍有效？
- **常见误区：** 文件哈希不同就认为独立，或因数据量大而忽略授权与血缘。

<a id="b05"></a>

### B05. 代码后训练怎样利用执行反馈？上线还要检查哪些接口细节？

- **难度 / 适用岗位：** 高级；后训练、代码服务。
- **原创作答要点：** 反馈可来自编译、测试、静态检查或任务验收；每种奖励都有覆盖限制。对生成、运行、修复形成闭环，同时隔离执行、限制资源并防止修改评分器。上线要固定 tokenizer、chat template、工具解析器和停止 token；[Qwen3-Coder 官方仓库](https://github.com/QwenLM/Qwen3-Coder)说明专用工具解析等注意事项。模型更强但模板不匹配时，可能工具调用完全失效。
- **深入追问：** 离线代码题高分而 Agent 频繁报工具解析失败，应如何定位？
- **常见误区：** 认为可执行奖励天然完整，或随意套用其他模型的工具调用格式。

<a id="b06"></a>

### B06. 仓库级上下文应该一次性塞入，还是分步检索？

- **难度 / 适用岗位：** 高级；代码检索、Agent。
- **原创作答要点：** 先识别入口、符号、依赖与失败测试，再按需读取，避免把生成目录和无关文件占满上下文。词法、符号图、向量检索和调用关系各有优势；长上下文可减少检索遗漏，却增加成本和干扰。设置 oracle 文件、检索文件和全仓库三种条件，测相关文件召回、最终修复与 token。记录引用的基准 commit，避免读取修复后的代码造成答案泄漏。
- **深入追问：** 召回目标文件仍无法修复，如何检验是上下文利用还是代码能力问题？
- **常见误区：** 超长窗口等于无需上下文策略，或只用文件名相似度评价检索质量。

<a id="b07"></a>

### B07. Agent-computer interface 为什么会显著影响软件 Agent？

- **难度 / 适用岗位：** 中高级；Agent 系统、工具设计。
- **原创作答要点：** [SWE-agent](https://arxiv.org/abs/2405.15793)研究适合 Agent 的搜索、浏览、编辑与执行接口。接口决定模型可见状态、错误反馈、动作粒度和恢复成本；过长日志可能隐藏关键错误，过弱编辑工具易破坏文件。对同一模型、同一任务和预算做接口消融，分别记录无效调用、编辑失败与任务成功率。界面优化收益不能全归为模型参数能力。
- **深入追问：** 工具输出截断后 Agent 循环重试，怎样改返回结构？
- **常见误区：** 给模型一个终端就默认拥有稳定的软件开发工作流。

<a id="b08"></a>

### B08. SWE-bench 衡量什么？读榜单时要核对哪些设置？

- **难度 / 适用岗位：** 中高级；代码 Agent、评测。
- **原创作答要点：** [SWE-bench](https://arxiv.org/abs/2310.06770)以真实仓库和 issue 构成修改代码任务，超出独立函数生成。结合 [官方仓库](https://github.com/SWE-bench/SWE-bench)核对 Full / Lite / Verified 等具体集合、容器与测试版本、是否允许多次尝试、文件定位方式和工具权限；不同集合分数不可直接比较。还要检查依赖安装失败、补丁应用失败和测试是否原本就失败。任务通过只保证相应验收范围，不能等同于真实项目无回归。
- **深入追问：** Agent 删除失败测试后测试全绿，验收系统如何避免误判？
- **常见误区：** 把旧论文基线当今日水平，或忽略模型与 scaffold 的共同贡献。

<a id="b09"></a>

### B09. 2026 年怎样评测 Agent 多轮开发造成的代码退化？

- **难度 / 适用岗位：** 研究级；软件 Agent、评测研究。
- **原创作答要点：** [SlopCodeBench](https://arxiv.org/abs/2603.24755)研究连续扩展自有代码时的结构侵蚀与冗余。应让后续需求建立在先前产物上，记录每轮正确率、变更影响范围、复杂度与重复，并对人工维护代码作合理匹配对照。指标只做代理，重构过度也会浪费成本；结合人工可维护性评审。核查时为 2026-05-07 的 v2，题量等与初版不同，不能混用二手摘要数字。
- **深入追问：** 重构让代码更整洁但短期功能成功率下降，怎样设计公平预算？
- **常见误区：** 当前所有测试通过就断言长期可维护，或将代码行数越少视为质量越高。

<a id="b10"></a>

### B10. 如何把代码 Agent 的执行能力限制在用户授权范围内？

- **难度 / 适用岗位：** 高级；Agent 安全、平台工程。
- **原创作答要点：** 划分读取、写入、网络、凭证、部署等权限，使用隔离工作区与最小权限；仓库文本、issue 和工具输出是数据，不自动授权外部发送或敏感操作。测试执行不能访问真实秘密，验收文件须防篡改；保存可审查 diff 与操作记录。2026 年 [Terminal-Bench](https://arxiv.org/abs/2601.11868)可用于思考真实终端任务，但基准成功率不替代部署安全审核。
- **深入追问：** 测试要求联网下载依赖时，如何控制允许的资源和凭证边界？
- **常见误区：** 将任意可执行命令交给模型，或认为编译器与包管理器没有外部副作用。

<a id="b11"></a>

### B11. VLM、VLA、传统模仿学习策略分别是什么关系？

- **难度 / 适用岗位：** 中级；具身智能、机器人学习。
- **原创作答要点：** VLM 建模视觉语言关系，VLA 进一步产生可用于控制的动作；模仿学习则描述从示范学习行为的方法，可用于训练 VLA。VLA 的输入常包括图像、语言与机器人状态，输出依具体系统定义，不一定是自然语言。[RT-2](https://arxiv.org/abs/2307.15818)将机器人动作表达为 token 并结合视觉语言训练，是典型案例。语义知识可帮助选物，但不等于掌握相应动力学。
- **深入追问：** 模型知道“易碎物要轻拿”，为何仍不能保证控制时不摔碎？
- **常见误区：** 把文字计划视为已经完成的低层控制，或将所有 VLA 都说成同一种动作表示。

<a id="b12"></a>

### B12. 动作离散 token 与连续动作头各有什么优劣？

- **难度 / 适用岗位：** 高级；VLA、动作表示。
- **原创作答要点：** 离散化便于统一序列目标，但有量化误差、token 长度和频率约束；连续输出能直接表达控制量，需处理多峰性、边界和训练稳定性。[OpenVLA](https://arxiv.org/abs/2406.09246)是开放 VLA 的阅读入口。必须明确输出的是关节、末端位姿、速度还是增量，以及坐标系、归一化和夹爪状态；不同定义不能简单逐维拼接比较。
- **深入追问：** 训练时动作归一化统计来自机器人 A，部署到机器人 B 会发生什么？
- **常见误区：** 将动作 token 直接视为电机指令，或忽视控制器与动作空间适配。

<a id="b13"></a>

### B13. π0 为什么使用 flow matching？与语言自回归有什么区别？

- **难度 / 适用岗位：** 高级；生成策略、具身模型。
- **原创作答要点：** [π0](https://arxiv.org/abs/2410.24164)将预训练 VLM 与流匹配动作建模结合，用连续生成机制表达动作分布。解释训练时从噪声到数据的路径与速度场目标、推理时积分求解，以及观测条件如何注入；不能把所有 flow 与 diffusion 实现混称同一算法。比较动作质量、采样步数、推理时延和控制频率，而非只看离线似然。页面截至核查日已修订至 2026-01-08。
- **深入追问：** 减少积分步数提高速度后，哪些任务最可能受影响？
- **常见误区：** 认为连续生成天然不需要反馈控制，或将流匹配训练解释为逐 token 交叉熵。

<a id="b14"></a>

### B14. Action chunking 为什么有效，又为什么可能降低反应速度？

- **难度 / 适用岗位：** 高级；机器人策略、实时系统。
- **原创作答要点：** 一次预测多步动作能减少模型调用、表达平滑连贯轨迹，但执行太长会忽略新观测和扰动。明确 chunk 长度、实际执行步数、重规划频率、状态延迟和异步推理。用移动目标、外部轻微扰动与遮挡恢复测试反应能力；比较固定动作频率下的成功率和约束违例。不能只用模型每秒输出多少动作衡量闭环系统实时性。
- **深入追问：** 摄像头与控制器时间戳不同步，策略会怎样表现？
- **常见误区：** 预测 50 步就必须开环执行完 50 步，或忽略网络和执行器时延。

<a id="b15"></a>

### B15. 多机器人数据如何共享？跨 embodiment 泛化难在哪里？

- **难度 / 适用岗位：** 高级；具身数据、基础策略。
- **原创作答要点：** 机器人在自由度、相机、末端工具、控制频率与状态含义上差异很大。数据需统一语义元数据、坐标和时间，不可假设相同维度即相同动作。比较共享骨干加适配器、统一空间与专门动作头；按机器人和任务家族分割评测。[OpenVLA](https://arxiv.org/abs/2406.09246)提供多示范数据训练案例，结果仍需在目标硬件与控制接口重测。
- **深入追问：** 某个机器人数据量占绝大多数，如何避免模型把其动作尺度当成默认？
- **常见误区：** 将动作零填充后混合训练就称为实现跨机器人统一。

<a id="b16"></a>

### B16. 为什么离线动作误差很小，真实执行仍可能失败？

- **难度 / 适用岗位：** 中高级；模仿学习、机器人评测。
- **原创作答要点：** 示范状态分布与部署状态不同，微小误差积累会进入模型没见过的状态；动作均方误差也可能惩罚多个合法动作、偏好无效平均。使用闭环 rollout，检查接触、抓取、恢复和终止判断。补充失败与恢复示范，按安全控制流程收集经授权的在线反馈；数据划分以完整轨迹或任务为单位，不能随机拆相邻帧制造虚高指标。
- **深入追问：** 两种都正确的绕障路线取平均，为什么可能直接撞上障碍？
- **常见误区：** 将离线 loss 当作真实任务成功率，或仅报告精选成功视频。

<a id="b17"></a>

### B17. 如何评估“新场景泛化”，而不是复现示范？

- **难度 / 适用岗位：** 研究级；具身研究、评测。
- **原创作答要点：** 区分新物体、新位置、新房间、新语言、新任务组合和新机器人；分别设置 holdout，防止同一物体实例或背景跨集合。2025 年 [π0.5](https://arxiv.org/abs/2504.16054)讨论异构共同训练与新环境泛化，是研究案例。报告每类任务、初始条件、试验次数、失败类型与置信区间；模拟结果与真实硬件结果分开，不能将视觉域随机化视为完整 sim-to-real 解决方案。
- **深入追问：** 新房间里所有物体均来自训练集，能支持哪些层面的泛化主张？
- **常见误区：** 使用一个从未拍摄的背景就宣称开放世界泛化，或不报告人为重置与干预。

<a id="b18"></a>

### B18. 高层语言规划、世界模型与低层控制怎样组成可靠系统？

- **难度 / 适用岗位：** 研究级；具身系统、机器人负责人。
- **原创作答要点：** 高层规划生成目标或子任务，世界模型预测候选后果，低层策略闭环执行；每层必须有可观察的成功与失败条件。对预测不确定性、规划可执行性和接触动力学分别校验，不能只把生成视频当事实。设置独立速度、力、碰撞和工作空间约束，感知失效时安全停止；任务长链评测同时记录效率、恢复与人工接管。语义合理的计划仍可能不适配真实硬件。
- **深入追问：** 世界模型生成“抓取成功”的画面，但真实物体未移动，下一步如何检测和恢复？
- **常见误区：** 将模型自述、想象轨迹和实际环境状态混为一谈。
