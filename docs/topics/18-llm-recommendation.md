## 业务链路与项目验收清单

下表是原创设计检查表；用于先明确可观测量及传统基线，再证明LLM模块的独立增益。每项指标须按实际场景定义窗口、分母和预算，不预设收益。

| 环节 | 数据 / 标签 | 传统基线 | LLM机制 | 上线指标 / 成本 |
|---|---|---|---|---|
| 物品理解 | 真实属性、内容与时间 | ID嵌入、内容编码 | 离线语义embedding/属性 | 事实正确率、更新与存储成本 |
| 用户序列 | 请求前事件、间隔、负反馈 | 池化、SASRec | 长序列摘要与序列建模 | 泄漏检查、兴趣保留、token成本 |
| 召回 | 会话—下一物品、有效ID | 协同过滤、双塔ANN | 语义ID生成 | Recall@K、合法率、解码预算 |
| 精排 | 曝光、点击、观看、转化 | DIN、多任务模型 | 候选条件语义特征/蒸馏 | 任务校准、p95、负反馈 |
| 重排 | 库存、已读、多样性约束 | 去重、约束重排 | 列表生成辅助 | 去重后候选数、覆盖、满意度 |
| 冷启动 | 新用户/新物品时间零点 | 热门与内容相似基线 | 内容迁移和受控探索 | 首交互质量、长尾覆盖、探索成本 |
| 解释与对话 | 明确偏好、可核验属性 | 规则说明、结构化过滤 | 证据内解释与偏好纠正 | 误导率、任务完成、交互成本 |
| 评测运行 | 时间快照、流量分组、trace | 时间切分、在线留出 | 语义模块消融与路由 | 长期留存、延迟、每千请求成本 |

### AC01. 传统推荐多阶段架构与LLM应怎样分工？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 画出用户/物品特征、召回、粗排、精排、重排与反馈。LLM可补语义内容、序列建模或生成候选，传统ID模型保留稀疏记忆和低延迟优势。按短视频、电商与内容社区定义目标；固定候选预算做分段消融，不默认生成式端到端替代全部链路。
- **深入追问：** 精排提升为何可能被召回上限限制？
- **常见误区：** 把推荐解释生成当推荐建模。
- **一手机制参考：** [Recommender Systems: A Primer](https://arxiv.org/abs/2302.02579)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC02. 语义ID推荐与文本推荐到底生成什么？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** TIGER将物品编码成语义码字序列并预测下一物品ID；自然语言推荐则生成描述或理由。设计码本时评估语义邻近、行为相关、碰撞和有效解码；候选输出必须映射真实可展示物品。与双塔比较全库召回、更新成本和冷启动，不仅比较文本相似。
- **深入追问：** 不存在的ID怎样处理？
- **常见误区：** LLM说出商品名就具备可靠全库检索。
- **一手机制参考：** [Recommender Systems with Generative Retrieval](https://arxiv.org/abs/2305.05065)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC03. 语义ID怎样兼顾内容语义和协同行为？

- **难度 / 适用岗位：** 中高级；推荐算法、生成式召回、内容与在线系统。

### AC04. 序列推荐训练样本与LLM上下文如何对齐？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 以请求时刻截断历史，保留曝光、点击、购买、跳过、间隔及顺序，不能使用未来评价。SASRec提供自注意力序列基线；LLM文本化需测token膨胀和离散ID兼容。训练/验证按时间分开，同一用户后续行为不能进入训练输入。
- **深入追问：** 把整月行为摘要用于月中请求有什么问题？
- **常见误区：** 长上下文自动消除数据泄漏。

### AC05. 长行为序列为何不能只取最近N条？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 短期意图、周期偏好和长期习惯不同。比较最近截断、时间衰减、分层池化、检索相关历史和LLM摘要；预算固定时测关键行为保留率及长尾兴趣召回。摘要绑定生成时间，负反馈和兴趣反转单列，防止历史人设永久固化。
- **深入追问：** 很久前购买的耐用品还应持续推荐吗？
- **常见误区：** 历史越长就越准确。
- **一手机制参考：** [Self-Attentive Sequential Recommendation](https://arxiv.org/abs/1808.09781)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC06. 候选相关兴趣与全局用户向量有何取舍？

- **难度 / 适用岗位：** 中高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 全局向量利于ANN与缓存，候选条件聚合更细但成本高；可先双塔召回再DIN式兴趣精排。离线LLM摘要作补充特征，不能重复编码未来行为。做冷用户、多兴趣与临时购买任务切片，检查收益是否只来自热门类别。
- **深入追问：** 为什么候选条件兴趣不能直接用标准ANN？
- **常见误区：** 把精排表达力无成本搬到全库召回。
- **一手机制参考：** [Deep Interest Network for Click-Through Rate Prediction](https://arxiv.org/abs/1706.06978)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC07. 新用户、新物品和新品类冷启动应如何分别处理？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 新用户可用当前会话、明确偏好和非个体热门基线；新物品利用核验内容表征并保留受控探索；新品类需额外评估属性语义和供给。分别定义时间零点与可用信息，报告首曝、首交互及长期收益。LLM合成互动不是观测真值。
- **深入追问：** 没有任何历史用户怎样避免过度画像？
- **常见误区：** 三种冷启动共享一个平均指标即可。
- **一手机制参考：** [Recommender Systems with Generative Retrieval](https://arxiv.org/abs/2305.05065)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC08. 推荐负样本怎样选才有意义？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 区分未曝光、曝光未点、跳过及明确不喜欢，采样需保留策略。全库检索用同一候选空间评估；困难负例避免其实相关的假负例。比较in-batch、均匀与流行度采样，记录训练目标和采样校正，防止用几十个随机负样本夸大全库效果。
- **深入追问：** 未曝光物品为什么不是确定负例？
- **常见误区：** 采样NDCG等同全量NDCG。
- **一手机制参考：** [Recommender Systems: A Primer](https://arxiv.org/abs/2302.02579)。引用用于相应机制及方法入口；本题实验与业务设计为原创延伸。

### AC09. LLM生成兴趣标签怎样建立质量闭环？

- **难度 / 适用岗位：** 中高级；推荐算法、生成式召回、内容与在线系统。

### AC10. 多任务排序怎样协调点击、观看、转化与满意度？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 先区分点击前后条件任务和直接曝光任务，统一标签窗口。共享底座与任务头可能负迁移，比较独立模型、共享模型和权重策略；损失量纲、样本密度和梯度冲突需诊断。线上以长期质量约束短期点击，不能简单相加未校准概率。
- **深入追问：** 点击高但投诉也高怎样处理？
- **常见误区：** 所有任务同时涨离线分就无目标冲突。

### AC11. 生成式推荐如何输出多样的合法列表？

- **深入追问：** 过滤后只剩少量候选如何补齐？
- **常见误区：** beam数就是不同有效物品数。

### AC12. 解释型推荐如何避免编造用户偏好或商品属性？

- **难度 / 适用岗位：** 中高级；推荐算法、生成式召回、内容与在线系统。

### AC13. 如何设计推荐的离线与线上评测？

- **难度 / 适用岗位：** 高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 按时间构建候选、标签和物品可用性快照，报告Recall/NDCG及新物品、长尾、覆盖。线上衡量任务收益、负反馈、延迟和长期留存；控制实验分流与污染。流行度和曝光分布变化可使离线指标失真，显著性与实际收益应分别报告。

### AC18. 开放设计：为内容社区构建可更新的对话式推荐。

- **难度 / 适用岗位：** 中高级；推荐算法、生成式召回、内容与在线系统。
- **原创作答要点：** 维护显式会话约束、短期意图和可撤回长期偏好，召回真实内容再排序。用户纠正即时覆盖旧摘要；内容新鲜度、负反馈、已读和多样性由规则及模型共同处理。实验以会话任务完成和长期满意度为主，解释只引用可验证内容。

- **常见误区：** 对话越长就认为个性化越好。
