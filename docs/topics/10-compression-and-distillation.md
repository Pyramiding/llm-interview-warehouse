# 10 · 量化、剪枝、蒸馏与小模型

> 本页 18 题是基于公开研究整理的**原创延伸题**，并非企业真题。来源核查于 2026-10-22，覆盖经典蒸馏、2023–2024 年压缩方法及 2025 年推理蒸馏案例；部分论文页面含 2026 修订。实际效果取决于模型、数据、kernel 与硬件，不能从位宽直接推出质量或速度。

<a id="c01"></a>

### C01. 量化、剪枝、蒸馏分别改变什么？

- **难度 / 适用岗位：**基础；压缩、推理、应用算法。
- **作答要点：**量化降低参数/激活/缓存表示精度；剪枝移除连接、通道、层或注意力结构；蒸馏以教师信号训练学生，架构可不同。三者可组合，但优化目标和误差来源不同。先确定显存、带宽、时延、能耗和质量约束，再选择方法；更小的文件不一定更快，较小模型也可能因输出更长增加端到端成本。
- **深入追问：**端侧问答与云端高并发场景会如何取舍？组合顺序为何影响最终效果？
- **常见误区：**把所有压缩都称为蒸馏；认为参数减少比例等于推理加速比例。

<a id="c02"></a>

### C02. 定量推导：线性量化中的 scale 与 zero point 如何计算？

- **难度 / 适用岗位：**基础至中等；压缩算法。
- **作答要点：**仿射量化可写 `q=clip(round(x/s)+z,qmin,qmax)`，反量化 `x_hat=s(q−z)`；非对称 min-max 常取 `s=(xmax−xmin)/(qmax−qmin)`，z 由零点映射并裁剪。示例将 [−1,2] 映到 uint8 [0,255]，s=3/255≈0.01176，z=85，x=0.6 映射至 q=136。明确舍入、裁剪与边界规则，避免实现不一致。
- **深入追问：**对称量化为何更简单？一个离群值会如何影响整个 tensor 的有效分辨率？
- **常见误区：**忽略 zero point 的整数约束；把 zero point 当浮点偏移直接用于整数乘法。

<a id="c03"></a>

### C03. Per-tensor、per-channel、group-wise 量化如何选？

- **难度 / 适用岗位：**中等；压缩、kernel。
- **作答要点：**粒度更细通常更能适应分布差异，但 scale、zero point 与索引元数据更多，kernel 也更复杂。group size 小未必总更快；需兼顾布局、对齐、硬件支持与校准样本。计算真实 bits/weight 时将元数据与未量化层计入，而不是只读文件名中的“4bit”。
- **深入追问：**group size=128、每组有 FP16 scale 与 zero point 时，单这两项增加多少？32/128=0.25 bit/weight。
- **常见误区：**认为所有 per-channel 都沿同一轴；只比较理论位宽，不检查打包与反量化路径。

<a id="c04"></a>

### C04. PTQ 与 QAT 有何区别，校准数据应怎么选？

- **难度 / 适用岗位：**中等；压缩、训练。
- **作答要点：**PTQ 在训练后估计范围、尺度或做局部重构；QAT 将量化误差纳入训练过程，通常用可导近似。校准集应覆盖目标语言、长度、任务、格式、工具 schema 与模态，且与最终评测分离；观察层级误差和端到端能力。预算不足时先用高质量 PTQ 基线，只有可证明的质量缺口才引入更昂贵训练。
- **深入追问：**只用短英文校准长中文代码模型会怎样？校准 perplexity 好但工具调用退化如何诊断？
- **常见误区：**把 PTQ 等同于无任何数据；用测试集反复挑尺度后仍宣称独立泛化。

<a id="c05"></a>

### C05. GPTQ 的核心优化目标是什么？

- **难度 / 适用岗位：**进阶；压缩算法。
- **作答要点：**[GPTQ](https://arxiv.org/abs/2210.17323) 是基于近似二阶信息的一次性权重量化方法。可从层输出重构 `min ||WX−W_hat X||²` 理解：不只最小化权重误差，还考虑输入激活使误差如何放大，并在逐步量化时补偿其他权重。面试中应说明校准数据与近似计算，不必把论文特定模型的“低损失”当所有模型保证。
- **深入追问：**为什么逐元素最近舍入不是输出误差的最优解？Hessian 近似和阻尼项起什么作用？
- **常见误区：**说 GPTQ 在做全模型梯度微调；认为相同 4bit 格式在所有运行时可以直接互换。

<a id="c06"></a>

### C06. AWQ 为什么看激活统计，而不只看权重绝对值？

- **难度 / 适用岗位：**进阶；量化、推理。
- **作答要点：**[AWQ](https://arxiv.org/abs/2306.00978) 用激活信息识别对输出重要的权重通道，并通过等价缩放减轻低比特量化误差。直观上同样的权重误差，乘上经常大幅激活的输入会产生更大输出扰动。需区分算法层的误差控制与 TinyChat 等实现的 kernel、融合、打包收益；当前页面含后续修订，复现实验应锁定版本。
- **深入追问：**等价变换在量化前为何不改变函数，量化后却有差别？保护重要通道是否必须混合位宽？
- **常见误区：**把 AWQ 描述成按激活大小剪枝；把论文的设备加速比无条件用于服务器。

<a id="c07"></a>

### C07. SmoothQuant 如何处理 activation outlier？

- **难度 / 适用岗位：**进阶；量化、训练系统。
- **作答要点：**[SmoothQuant](https://arxiv.org/abs/2211.10438) 用等价的通道缩放，把部分激活量化难度迁移到权重，使 W8A8 更可行。对 `Y=XW` 可理解为 `Y=(X S^-1)(S W)`，S 为对角缩放；浮点等价不代表量化误差相同。平滑系数应在独立校准集选择，检查长尾任务和目标硬件的 INT8 路径。
- **深入追问：**为什么只降低激活动态范围可能让权重量化更难？缩放可以融合到哪些相邻算子？
- **常见误区：**认为 outlier 被删除；把 W8A8 的“8bit”误读为整条服务链都没有高精度计算。

<a id="c08"></a>

### C08. QLoRA 的 4bit 在哪里，为什么还能反向传播？

- **难度 / 适用岗位：**中等；微调、压缩。
- **作答要点：**[QLoRA](https://arxiv.org/abs/2305.14314) 冻结低比特底座并训练低秩 adapter，计算时可反量化到较高精度，梯度流经计算进入 adapter。论文提出 NF4、双重量化和 paged optimizer 等内存优化；不能说底座的整数权重做了普通全参更新。训练内存还包括 adapter 状态、激活和临时张量，推理部署需验证 adapter 合并与再量化误差。
- **深入追问：**NF4 与均匀 INT4 有何不同？合并 LoRA 后为什么不能保证保持原先量化结果？
- **常见误区：**将 QLoRA 当作专门推理引擎；以底座冻结为由认为不需要保存激活。

<a id="c09"></a>

### C09. KV cache 量化与权重量化为什么是两类问题？

- **难度 / 适用岗位：**进阶；推理、压缩。
- **作答要点：**权重离线固定，KV 随请求、位置与上下文动态产生；缓存误差还会影响后续 attention。K 与 V 的分布、误差传播与适合的分组轴可能不同，[KIVI](https://arxiv.org/abs/2402.02750) 研究了 K 按通道、V 按 token 的非对称处理。评估应包含长上下文、检索、数值任务与不同 batch，计入 scale、残留高精度区与解量化开销。
- **深入追问：**最近一段保留高精度有何作用？cache 变小后为何吞吐提升可能超过单请求加速？
- **常见误区：**把 2bit cache 当整个模型 2bit；只测短 prompt 的 perplexity。

<a id="c10"></a>

### C10. 非结构化、半结构化和结构化剪枝有何区别？

- **难度 / 适用岗位：**中等；压缩、系统。
- **作答要点：**非结构化移除任意权重，表达灵活但需要高效稀疏 kernel；半结构化如 N:M 约束局部模式，便于硬件利用；结构化删除通道、头或层，形成更小稠密图，但能力损失可能更大。[SparseGPT](https://arxiv.org/abs/2301.00774) 是一次性剪枝研究来源。应同时报告稀疏率、实际存储、端到端延迟与质量，而非只报告零元素占比。
- **深入追问：**50% 的零权重为什么可能不加速？结构化删除头后哪些矩阵维度要同步变更？
- **常见误区：**把权重置零等同于减少 FLOPs；忽略稀疏索引元数据。

<a id="c11"></a>

### C11. Wanda 的重要性指标为何同时使用权重与激活？

- **难度 / 适用岗位：**进阶；压缩算法。
- **作答要点：**[Wanda](https://arxiv.org/abs/2306.11695) 使用权重幅度与对应输入激活范数的组合评估重要性，比单看权重更关注对输出的影响。它与需要二阶重构的方案计算成本不同。重要性不等于全局因果贡献；剪枝比例、层间分配、任务分布及后续恢复训练都需独立验证。
- **深入追问：**激活分布改变时原重要性排序会失效吗？统一稀疏率与层自适应稀疏率怎样比较？
- **常见误区：**把 AWQ、Wanda 都简化成“保留最大权重”；以校准误差代替完整能力评测。

<a id="c12"></a>

### C12. 经典知识蒸馏的温度、KL 方向与 T² 是什么？

- **难度 / 适用岗位：**中等至进阶；训练算法。
- **作答要点：**教师和学生的软分布为 `p_T=softmax(z/T)`；常见损失 `λ T² KL(p_teacher,T || p_student,T)+(1−λ) CE(y,p_student,1)`。提高温度可显露非最大类别关系，T² 用于补偿常见推导下梯度缩放，具体权重仍需实验。KL 方向改变优化偏好，不能互换。[Hinton 等经典论文](https://arxiv.org/abs/1503.02531) 是起点；自回归 token 训练还需处理序列分布偏移。
- **深入追问：**只拿到教师文本时能否做上述 logit 蒸馏？教师与学生词表不同如何对齐？
- **常见误区：**温度越高越好；把教师正确率当学生能力上限或保证。

<a id="c13"></a>

### C13. Logit、特征、序列和推理轨迹蒸馏分别需要什么？

- **难度 / 适用岗位：**进阶；蒸馏、后训练。
- **作答要点：**logit 蒸馏需分布与词表对齐；特征蒸馏需层/维度映射；序列蒸馏只需教师生成文本；推理轨迹蒸馏额外提供中间步骤或过程信号。[Distilling Step-by-Step](https://arxiv.org/abs/2305.02301) 用理由作为额外监督。轨迹看起来详细不代表忠实或正确，应做最终结果校验、过程过滤和无轨迹对照，避免学生只学冗长格式。
- **深入追问：**更长教师轨迹为何可能伤害小模型？只蒸馏正确答案会丢失什么信息？
- **常见误区：**把所有教师输出都当高质量训练数据；认为学生生成相同措辞就学会了相同推理。

<a id="c14"></a>

### C14. 如何理解 DeepSeek-R1 的小模型蒸馏案例？

- **难度 / 适用岗位：**中等至进阶；推理训练、蒸馏。
- **作答要点：**[DeepSeek-R1 报告](https://arxiv.org/abs/2501.12948) 发布基于 Qwen/Llama 的多个 dense 蒸馏模型，说明将强教师生成数据用于训练学生是一条可行研究路线。它不意味着学生复制了教师权重、拥有同等全部能力，或所有任务都靠蒸馏最优。比较同底座、同训练预算下的 SFT、蒸馏、直接 RL 与混合方案；明确论文初稿为 2025，当前页面含 2026 修订。
- **深入追问：**教师数据筛选、长输出预算与验证器如何影响小模型？如何防止基准污染？
- **常见误区：**把名字里“Distill”理解为低比特量化；忽略学生底座原有能力。

<a id="c15"></a>

### C15. 剪枝后蒸馏与从头训练小模型如何公平比较？

- **难度 / 适用岗位：**高级；压缩研究、负责人。
- **作答要点：**[Minitron 相关论文](https://arxiv.org/abs/2407.14679) 研究结构化剪枝与知识蒸馏组合。公平比较需说明是否把已有教师预训练成本视为沉没成本；比较训练 token、教师前向成本、搜索成本、恢复训练和最终部署性能。选择目标宽度与深度要兼顾 kernel shape 和能力切片，而非仅接近参数数量。
- **深入追问：**对已有大模型家族与从零新项目，经济账为何不同？深度剪枝与宽度剪枝如何设计消融？
- **常见误区：**把“仅额外训练 token 少”写成“全生命周期成本同等比例减少”；不计教师推理。

<a id="c16"></a>

### C16. 系统设计：单张 24 GiB 显卡部署 14B 模型，应怎样规划？

- **难度 / 适用岗位：**高级；压缩、推理架构。
- **作答要点：**FP16 权重约 28 GB 十进制，已经超出 24 GiB；4bit 纯权重理想约 7 GB，但还需 scale、未量化层、KV、workspace 和安全余量。先定义目标质量、上下文与并发，再验证硬件支持的量化格式；用 I03 的 KV 公式估算。比较低比特 14B、小模型蒸馏与 CPU offload 的真实 SLO，不能仅凭“文件能放下”宣称可生产服务。
- **深入追问：**并发从 1 增至 16 后瓶颈可能如何迁移？若工具调用质量损失 5 个百分点如何决策？
- **常见误区：**直接用 24 除权重大小算并发；忽略长上下文和峰值临时内存。

<a id="c17"></a>

### C17. 排障：量化后总体 perplexity 正常，但业务质量明显下降，如何查？

- **难度 / 适用岗位：**进阶；压缩评测。
- **作答要点：**按语言、长度、数学、代码、工具参数、格式和拒答切片；核对 tokenizer、模板、RoPE、量化导出与加载格式。逐层比较激活/输出误差，寻找对特定能力敏感的层，再尝试保留高精度、扩大校准覆盖或修改粒度。用固定样本的浮点模型作对照，确认不是 prompt 或运行时变化。
- **深入追问：**首 token 分布差异小而长输出偏离为何可能发生？怎样检测 kernel 回退或错读 zero point？
- **常见误区：**把单一 perplexity 当所有能力的充分代理；不断调参使用同一测试集。

<a id="c18"></a>

### C18. 如何报告压缩收益与模型退化，使结论可信？

- **难度 / 适用岗位：**中等至高级；研究、推理平台。
- **作答要点：**给出原模型、校准/训练数据、量化粒度、实际 bits/weight、稀疏模式、硬件与 kernel 版本；同时报告文件、峰值显存、TTFT、TPOT、吞吐、功耗及质量切片。蒸馏还要计入教师调用和数据过滤。多档配置形成质量—成本前沿，展示失败案例与误差条，避免只挑一个最有利 benchmark。
- **深入追问：**输出长度不同怎样比较时延与成本？压缩后平均质量持平但安全边界退化该如何呈现？
- **常见误区：**将理论压缩率当实测显存收益；跨硬件、跨模板比较却不披露。
