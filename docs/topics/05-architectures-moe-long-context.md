# 模型架构、MoE、长上下文与状态空间模型

> 18 道原创延伸题；基于公开技术报告设计，不代表企业真实题库。核验截止：2026-10-22。以 2023—2025 年公开研究为主要近期材料，保留 MQA、Switch 等必要基础；个别论文在 2026 年修订，不将修订年份误记为首发年份。

## 对照阅读

架构选择同时影响质量、训练稳定性、权重容量、KV cache、通信与服务成本。下文算例均先固定简化假设；不能用激活参数量单独预测吞吐，也不能用配置文件里的最大长度代表有效长上下文能力。

<a id="m01"></a>

### M01. Decoder-only、encoder-only 与 encoder-decoder 的核心区别是什么？

**难度 / 岗位：** 基础；算法、应用。

**作答要点：** encoder-only 通常用双向上下文表示输入；decoder-only 用因果条件分解统一生成；encoder-decoder 先编码输入，再让解码器通过 cross-attention 条件生成。比较时关注监督目标、输入/输出长度和是否需要增量生成，不能只用“哪种更先进”排序。decoder-only 的普及还涉及规模化训练和服务生态，不是对所有检索、分类或序列转换任务的严格优势证明。起点见 [Transformer](https://arxiv.org/abs/1706.03762)。

**深入追问：** cross-attention 的 Q、K、V 各来自哪部分？为什么编码器输出可以在生成时缓存？

**常见误区：** decoder-only 等于没有位置编码；把双向 attention 当成可直接用于无泄漏自回归生成。

<a id="m02"></a>

### M02. MHA、MQA、GQA 如何影响质量与 KV cache？

**难度 / 岗位：** 基础；算法、推理、系统。

**作答要点：** MHA 每个 query 头配各自 KV；MQA 所有 query 头共享一组 KV；GQA 介于两者之间，多个 query 头共享每个 KV 头。它们主要减少 KV 投影、缓存与读带宽，query 头仍可保持多头。共享可能改变质量，不能把未经训练的 checkpoint 简单改配置就视为等价。参见 [MQA](https://arxiv.org/abs/1911.02150)、[GQA](https://arxiv.org/abs/2305.13245)。

**深入追问：** 将 32 个 query 头、8 个 KV 头映射为每组 4 个 query，实际 kernel 是否需要物理复制 KV？

**常见误区：** 以为 GQA 把 Q 头数也一定缩成 KV 头数；忽略质量与带宽折中。

<a id="m03"></a>

### M03. 手算一个 GQA 模型的 KV cache 大小。

**难度 / 岗位：** 进阶；推理、系统。

**作答要点：** 若各层相同，理想有效数据大小为 `2·B·T·L·h_kv·d_head·b`，2 表示 K/V，b 为每元素字节。例 `B=1,T=32768,L=32,h_kv=8,d_head=128,b=2`，结果 `2³² bytes=4 GiB`；若 MHA 的 hkv=32，则 16 GiB。未含 block 碎片、对齐、元数据、共享前缀和并行复制；也不能直接套用于 MLA。结构见 [GQA](https://arxiv.org/abs/2305.13245)。

**深入追问：** batch 翻倍和上下文翻倍分别如何变化？prefix cache 命中后是每请求都独立计费存储吗？

**常见误区：** 忘记 K/V 的系数 2；把 GB 与 GiB 混用；使用 query 头数计算 GQA cache。

<a id="m04"></a>

### M04. MLA 与 GQA 的压缩思路有什么不同？

**难度 / 岗位：** 研究；架构、推理。

**作答要点：** GQA 在头之间共享 KV；MLA 将 KV 联合压缩为低维潜变量，并在实现允许时把部分投影吸收到计算中，减少需要缓存的维度。旋转位置项与可吸收投影并非天然兼容，因此 DeepSeek-V2 采用解耦的 RoPE 设计。比较 cache 时应按实际缓存的潜变量和位置分量算，而非照搬 `h_kv×d_head`。见 [DeepSeek-V2](https://arxiv.org/abs/2405.04434)。

**深入追问：** 为什么训练时与增量解码时可使用不同等价计算路径？矩阵吸收后 FLOPs、带宽与 kernel 形状怎样变化？

**常见误区：** 把 MLA 叫成更少 KV 头的 GQA；认为低秩压缩自动保持任意已有 checkpoint 的质量。

<a id="m05"></a>

### M05. MoE 的总参数与激活参数分别影响什么？

**难度 / 岗位：** 基础；算法、训练、系统。

**作答要点：** sparse MoE 通常按 token 选择少量 FFN 专家；总参数反映需要容纳的全部权重，激活参数近似反映每 token 经过的部分计算。玩具例：共享部分 2B，8 个各 1B 专家、top-2，则总量 10B、单 token 约激活 4B。实际每层路由、attention 和共享专家需逐项计数。训练 FLOPs 不能直接套 `6N_totalD`；激活参数的近似也需补 attention、重算等开销。激活参数更不能单独预测显存或墙钟耗时。见 [Mixtral](https://arxiv.org/abs/2401.04088)。

**深入追问：** 为什么某 MoE 激活参数少，单请求延迟却可能更高？低 batch 时专家权重加载有什么代价？

**常见误区：** 把“8×7B”机械算为 56B；以为每次只激活两个专家就只需存两个专家。

<a id="m06"></a>

### M06. Token-choice 路由的 top-k 与专家容量如何工作？

**难度 / 岗位：** 进阶；MoE、系统。

**作答要点：** 路由器从隐藏状态得到专家得分，选择 top-k 并组合专家输出；入选 gate 权重通常可微，但离散选择本身不是普通连续操作。若 T 个 token、E 个专家、每 token 分配 k 次，容量可按 `C≈ceil(c·kT/E)` 设置，c 为 capacity factor。超容量时可能丢弃、重路由或采用 dropless 实现；这些会改变质量和系统代价。基础见 [Switch Transformer](https://arxiv.org/abs/2101.03961)。

**深入追问：** top-1 与 top-2 在通信、容量、训练信号和负载方面有什么取舍？token 数按本地 rank 还是全局定义？

**常见误区：** 认为 top-k selection 没梯度就整个 router 无法训练；默认所有实现都会丢 token。

<a id="m07"></a>

### M07. 为什么 MoE 会负载不均，辅助平衡损失怎样理解？

**难度 / 岗位：** 进阶；MoE、研究。

**作答要点：** 早期随机优势、专家强弱和数据分布会形成正反馈，使少量专家过载。Switch top-1 的一种辅助项是 `L_bal=αE∑ᵢfᵢPᵢ`，f 是实际路由 token 比例，P 是平均 router 概率；它结合利用率与概率分布，而不只是最大化熵。均匀分配时未乘 α 的值为 1，不是 0。系数过大可能干扰任务学习。见 [Switch](https://arxiv.org/abs/2101.03961)。

**深入追问：** 全局统计均匀是否代表每个设备、每个 microbatch 都均匀？router entropy 高是否足以证明无热点？

**常见误区：** 只看平均负载、不看最大/最小与等待时间；认为专家必须均分所有语义任务。

<a id="m08"></a>

### M08. 细粒度专家与共享专家分别解决什么问题？

**难度 / 岗位：** 研究；MoE、架构。

**作答要点：** 细分专家并相应调整激活数量，可在近似计算预算下提高组合灵活性；共享专家尝试吸收通用知识，使 routed 专家更专门化。需同时比较单专家宽度、总容量和激活量，否则很容易把更多计算当作结构收益。DeepSeekMoE 提出相关设计，DeepSeek-V3 延续并加入新的负载与系统设计。见 [DeepSeekMoE](https://arxiv.org/abs/2401.06066)、[DeepSeek-V3](https://arxiv.org/abs/2412.19437)。

**深入追问：** 共享专家是否一定学成“语法专家”？如何通过消融而非可视化标签检验其作用？

**常见误区：** 把专家编号直接对应人工学科；以为 MoE 就是多个完整聊天模型投票。

<a id="m09"></a>

### M09. Expert parallel 与 tensor parallel 有何区别，MoE 为什么常受通信限制？

**难度 / 岗位：** 进阶；训练、系统、推理。

**作答要点：** expert parallel 将不同专家分布在设备上，需要把 token 按路由 dispatch 再 combine，常出现 all-to-all；tensor parallel 拆单个矩阵/层，通常涉及不同形式的聚合通信。MoE 小专家或低 batch 容易变成通信与 kernel launch 主导；拓扑、跨节点专家分布和负载倾斜影响显著。实际优化可参考 [DeepSeek-V3](https://arxiv.org/abs/2412.19437)。

**深入追问：** 在 FLOPs 不变时把专家数量翻倍，为何可能减速？怎样测量通信与计算的重叠是否有效？

**常见误区：** 把 all-to-all 与 all-reduce 混称；只计算矩阵 FLOPs，忽略 dispatch 元数据和重排。

<a id="m10"></a>

### M10. 延长上下文为何不能只修改 max_position_embeddings？

**难度 / 岗位：** 基础；长上下文、应用。

**作答要点：** 需要同时满足位置表示、训练长度分布、有效信息利用、显存和吞吐。配置能接受 128K token，只说明接口/实现可容纳，不证明中间证据可被找到，更不证明多跳推理和摘要质量。用位置移动、干扰数量和长度阶梯测试实际能力。见 [Lost in the Middle](https://arxiv.org/abs/2307.03172)。

**深入追问：** 4K 训练模型输入 32K 不报错，为什么可能仍然严重退化？如何区别位置问题与证据稀释？

**常见误区：** 用一次 passkey 检索通过证明长文档所有任务都可靠；忽略输出长度与输入长度竞争预算。

<a id="m11"></a>

### M11. Position Interpolation 如何扩展 RoPE 长度？

**难度 / 岗位：** 进阶；长上下文、研究。

**作答要点：** 设原训练长度 L、目标 L'，把位置索引缩放为 `m'=m·L/L'`，让新位置范围映入训练中较熟悉的角度区间。它减少直接外推风险，却改变相邻位置的相位分辨率，通常需要匹配训练。例从 4K 到 32K，缩放因子为 1/8。不能只根据数学可计算性断言质量。见 [Position Interpolation](https://arxiv.org/abs/2306.15595)。

**深入追问：** 长文本收益和原短文本性能如何共同评估？统一缩放位置与改变不同频段的频率有什么区别？

**常见误区：** 把插值说成增加模型参数；在缓存已有 key 后随意改变位置缩放约定。

<a id="m12"></a>

### M12. YaRN 与统一位置插值相比，关注哪些额外设计？

**难度 / 岗位：** 研究；长上下文、架构。

**作答要点：** RoPE 各频段在训练长度内转过的圈数不同，对统一缩放的敏感性也不同；YaRN 引入分频段的插值/外推处理与注意力缩放等设计，提高上下文扩展效率。回答应解释动机及如何验证短长文本取舍，不必在未指定版本时背硬编码常数。该论文初次提交为 2023-08-31，页面另有 2026-02-06 修订。见 [YaRN](https://arxiv.org/abs/2309.00071)。

**深入追问：** 只增加高频或低频的缩放，分别可能怎样影响局部区分与远距离模式？应固定哪些变量做消融？

**常见误区：** 把 YaRN 当成检索算法；将一个模型家族的 rope_scaling 配置直接套给另一家族。

<a id="m13"></a>

### M13. Sliding window attention 的感受野与复杂度怎样计算？

**难度 / 岗位：** 进阶；架构、推理。

**作答要点：** 单层每位置只看约 w 个历史位置，attention 计算约 `O(Twd)`；若层层局部因果窗口，L 层理论可传播范围约 `1+L(w−1)`，但这不意味着所有远处细节都能无损传递。rolling cache 可限制保留窗口，具体模型也可能混合全局层。Mistral 7B 展示了 SWA/GQA 设计。见 [Mistral 7B](https://arxiv.org/abs/2310.06825)。

**深入追问：** 两个相距很远的 token 能否经多层间接作用？为什么这种路径不等价于一层全局直接寻址？

**常见误区：** 看到滑窗就认为整个模型只能读 w token；把理论感受野当实际有效记忆长度。

<a id="m14"></a>

### M14. Ring Attention 或上下文并行解决的是什么瓶颈？

**难度 / 岗位：** 研究；训练系统、长上下文。

**作答要点：** 将超长序列的 token/激活分散到设备，计算局部 Q 并依次传递或交换 K/V 块，配合在线 softmax 合并结果。目标是跨设备扩展可训练长度与内存容量，并尝试重叠通信；并没有凭空消除 dense attention 的总二次算术量。实际速度依赖拓扑、块大小及计算通信比。见 [Ring Attention](https://arxiv.org/abs/2310.01889)。

**深入追问：** 序列翻倍、设备也翻倍，总 FLOPs 和单设备显存各会怎样变化？因果 mask 会怎样改变负载平衡？

**常见误区：** 将上下文并行等同于 tensor parallel；只报最大可训练长度，不报通信和利用率。

<a id="m15"></a>

### M15. 如何构建比单针检索更可靠的长上下文评测？

**难度 / 岗位：** 进阶；评测、长上下文、应用。

**作答要点：** 在不同长度和证据位置测试单/多证据检索、相似干扰、跨段关联、聚合、顺序依赖、长文摘要及拒答；控制原始文本、tokenizer 与输出预算。用真实文档和合成任务互补，报告随长度退化曲线和失败分类。RULER 说明标称窗口之外还需有效长度评估，不能用单一成功案例代表全能力。见 [RULER](https://arxiv.org/abs/2404.06654)、[Lost in the Middle](https://arxiv.org/abs/2307.03172)。

**深入追问：** “针”特别醒目、随机无意义干扰和真实相似文档分别可能怎样偏置结果？

**常见误区：** 只测试证据位于最后；对不同模型使用不同数量的有效证据。

<a id="m16"></a>

### M16. Mamba 的 selective state space 与 attention 如何取舍？

**难度 / 岗位：** 研究；架构、系统。

**作答要点：** SSM 用状态递推压缩历史；Mamba 让部分状态空间参数依赖输入，以选择性保留信息，并设计硬件友好的并行扫描。固定隐藏/状态维度时，序列计算可线性增长，增量状态不随历史 token 数线性膨胀；但历史被压缩，精确内容寻址和长距检索行为与显式 KV 不同。速度与质量优势需按规模、任务和硬件实测。见 [Mamba](https://arxiv.org/abs/2312.00752)。

**深入追问：** “推理状态固定大小”为什么不等于训练时完全不保存激活？多请求 batch 怎样管理各自状态？

**常见误区：** 线性复杂度就断言任何长度任何硬件都更快；把固定状态视为无限精确记忆。

<a id="m17"></a>

### M17. Mamba-2、混合架构和线性注意力应怎样比较？

**难度 / 岗位：** 研究；架构、研究。

**作答要点：** Mamba-2 从状态空间与结构化注意力的联系发展结构化状态空间对偶；线性注意力通过不同特征或递推形式避免显式 T×T 注意力；混合模型在部分层保留注意力，以取舍内容检索与压缩状态。比较时固定参数、训练 token、算力和上下文任务，还看服务 kernel 的成熟度。不要把所有“线性”模型视为同一机制。见 [Transformers are SSMs / Mamba-2](https://arxiv.org/abs/2405.21060)。

**深入追问：** 在键值精确检索、自然语言困惑度和长序列吞吐之间可能出现哪些不一致排序？

**常见误区：** 只比较理论阶数；把混合架构有 attention 层理解成与纯 Transformer 完全一样。

<a id="m18"></a>

### M18. 如果设计一个长上下文 MoE 服务，应如何做架构决策？

**难度 / 岗位：** 研究；研究、系统、技术负责人。

**作答要点：** 从请求分布的输入/输出长度、并发、首 token/逐 token 延迟及质量门槛开始。分别预算总权重、激活、KV/状态和通信；比较 dense/MoE、GQA/MLA、全局/滑窗及量化；最后测真实流量的尾延迟、热点专家和长文有效性。使用成本—质量曲线，保留容量与失败回退方案。实际权衡可读 [DeepSeek-V2](https://arxiv.org/abs/2405.04434)、[Qwen3](https://arxiv.org/abs/2505.09388)。

**深入追问：** 如果长输入、短输出占多数，优化 prefill 还是 decode？如果反过来，又为何改变选择？

**常见误区：** 按单张榜单选架构；用平均吞吐掩盖 P95/P99 延迟与难例失败。
