# 指令微调、PEFT 与蒸馏

> 18 道原创延伸题；基于公开论文与框架文档，不作为企业真题背书。核验截止：2026-10-22。实施类问题应同时说明基础模型、数据版本、训练配置和部署方式；没有通用最优的 LoRA rank 或学习率。

## 学习路线

先掌握监督信号与 mask，再推导 LoRA，最后设计训练—合并—部署的一致性校验。参数高效不等于所有训练成本按可训练参数比例下降：冻结的主干仍参与前向与梯度传播。与 [预训练](02-pretraining-and-data.md)、[对齐](04-alignment-and-rl.md) 联读。

<a id="s01"></a>

### S01. SFT 的训练目标是什么，哪些 token 应计算损失？

**难度 / 岗位：** 基础；算法、后训练、应用。

**作答要点：** 条件生成目标可写为 `L=−∑ₜmₜlogπθ(yₜ|x,y<t)/∑ₜmₜ`。m 通常只选择期望模型生成的 assistant 片段，也可按任务设计对全序列计算；必须说明选择。padding、user/system 提示、工具输出是否计损失不能含糊。teacher forcing 的输入/标签移位只应执行一次。相关实现选项见 [TRL SFTTrainer](https://huggingface.co/docs/trl/main/en/sft_trainer)。

**深入追问：** 多轮对话只训最后一轮与训练所有 assistant 轮各适用于什么情境？空 target 样本如何处理？

**常见误区：** 将 input_ids 整段复制为 labels 就认为一定正确；忘记忽略 padding。

<a id="s02"></a>

### S02. Chat template 为什么属于模型接口的一部分？

**难度 / 岗位：** 基础；算法、应用、部署。

**作答要点：** 模型接收的是 token 序列；角色、轮次、结束标记和 assistant 起始前缀均由模板编码。训练与推理模板不一致会改变条件分布，导致角色混淆、不停生成或输出模板字符。使用基础模型对应的模板，检查 BOS/EOS 是否重复加入，并保存 tokenizer 与模板版本。文档见 [Chat templates](https://huggingface.co/docs/transformers/main/chat_templating)。

**深入追问：** “继续最后一条 assistant 消息”和“开启新 assistant 回复”为什么不能总同时使用？

**常见误区：** 以为所有模型都兼容同一角色字符串；只改文本模板不验证 token id。

<a id="s03"></a>

### S03. 高质量 SFT 数据应如何定义，而不是只看数量？

**难度 / 岗位：** 进阶；数据、后训练。

**作答要点：** 质量包含指令可解性、回答正确性、格式一致、任务覆盖、长尾难度及用户分布匹配。按能力矩阵分层采样，去除重复与矛盾标签；对代码、数学和工具任务引入可执行检查。LIMA 展示了少量精挑样本的价值，但其结果不是“任意模型用 1000 条就足够”的定律。见 [LIMA](https://arxiv.org/abs/2305.11206)、[Flan](https://arxiv.org/abs/2210.11416)。

**深入追问：** 如果样本数不变，只扩大任务多样性，怎样设计对照组？如何审查模板化回答的偏差？

**常见误区：** 按回答长度或教师评分单维排序；把某研究的聊天偏好胜率当成全面能力结论。

<a id="s04"></a>

### S04. LoRA 的公式、形状与参数节省如何推导？

**难度 / 岗位：** 基础；算法、训练。

**作答要点：** 采用列向量约定，`W∈R^{d_out×d_in}`，`A∈R^{r×d_in}`、`B∈R^{d_out×r}`，`W'=W+sBA`，经典缩放 `s=α/r`；W 冻结。可训练量从 `d_out·d_in` 变为 `r(d_in+d_out)`。对 4096×4096、r=8，是 65536 对 16777216，约 0.391%。这些是单矩阵估算，实际模型还取决于 target_modules。见 [LoRA](https://arxiv.org/abs/2106.09685)。

**深入追问：** 若 32 层只改 Q/V 两个方阵，约 419 万 LoRA 参数；加 embedding 和输出头后为什么需重算？

**常见误区：** A、B 形状相反却不说明行/列约定；把低秩增量误说成原始 W 低秩。

<a id="s05"></a>

### S05. LoRA 为什么常初始化一侧为零，另一侧随机？

**难度 / 岗位：** 进阶；算法、训练。

**作答要点：** 令 B=0、A 随机，则初始 `BA=0`，模型函数与基础模型一致。此时第一步 A 的梯度为零，因为包含 B；B 的梯度通常非零，随后两者共同学习。若 A、B 同时为零，双线性参数化会使两者梯度均为零。不同初始化方法可以改变学习动态，不能把经典初始化当成唯一正确实现。参见 [LoRA](https://arxiv.org/abs/2106.09685)、[PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora)。

**深入追问：** 推导 `∂L/∂A=sBᵀG`、`∂L/∂B=sGAᵀ`，其中 G 为对 W' 的梯度。

**常见误区：** 认为 A 第一轮梯度为零就是实现失败；为“稳定”把两个矩阵都初始化为零。

<a id="s06"></a>

### S06. Rank、alpha、学习率和 target_modules 应如何联合选择？

**难度 / 岗位：** 进阶；后训练、研究。

**作答要点：** rank 控制增量容量与存储，alpha 通过缩放影响更新量级；target_modules 决定能改变哪些计算。优先固定数据与训练预算，从小范围 rank、缩放、学习率组合做验证，观察目标任务与通用回归。只改 Q/V、全部 attention、再加 FFN 是不同假设，不应一次全部改变。部分实现采用 `α/√r` 等变体，需明确版本和配置。见 [PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora)。

**深入追问：** rank 增大但不涨分，可能是容量之外的哪些限制？怎样比较同参数预算不同模块分配？

**常见误区：** 把 rank=8 或 64 当普适最优；以为 alpha 只影响保存文件大小。

<a id="s07"></a>

### S07. 冻结主干后，为什么 LoRA 仍然需要不少激活显存？

**难度 / 岗位：** 进阶；训练、系统。

**作答要点：** LoRA 减少主干梯度、优化器状态及可能的权重副本；但梯度还需穿过冻结层传到上游适配器，前向激活与反向中间量不会全部消失。长序列时激活可能主导峰值。应拆分权重、适配器梯度/状态、激活、临时缓冲与通信；用 checkpointing、packing 和高效 attention 优化不同部分。见 [LoRA](https://arxiv.org/abs/2106.09685)、[QLoRA](https://arxiv.org/abs/2305.14314)。

**深入追问：** 只训最后一层和每层插入 LoRA，反向需要保存的激活范围是否一样？

**常见误区：** 可训练参数只有 0.1%，就宣称显存与 FLOPs 都只剩 0.1%。

<a id="s08"></a>

### S08. QLoRA 的“4-bit 训练”究竟指什么？

**难度 / 岗位：** 进阶；训练、量化。

**作答要点：** 主干权重冻结并以低比特形式存储，计算时解量化到计算精度，梯度流经主干运算更新高精度适配器。NF4 采用适应近似正态权重分布的非均匀码本；double quantization 压缩量化常数；paged optimizer 管理内存峰值。不能由此推断所有激活、梯度、累加和优化器均为 4 位。原研究见 [QLoRA](https://arxiv.org/abs/2305.14314)。

**深入追问：** 7B 权重的理想 4-bit 原始数据约 3.5 GB，为什么实际运行远高于此？

**常见误区：** 认为 NF4 等于普通有符号 int4；拿论文单卡案例当任意配置的显存承诺。

<a id="s09"></a>

### S09. LoRA 是否可以无损合并进主干？量化主干又如何？

**难度 / 岗位：** 进阶；部署、训练、量化。

**作答要点：** 浮点线性层在适配器固定、推理态下，可构造 `W_merge=W+sBA`，数学上与串接计算对应；浮点舍入和 kernel 路径仍可能带来微小差异。量化主干若解量化、合并、再量化，会引入新的量化误差；不同库对合并支持也不同。部署前比较未合并、合并、导出版本的 logits 与任务指标。见 [PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora)。

**深入追问：** 为什么训练时 dropout 开启不能直接等价为一个固定合并矩阵？怎样回退到原适配器？

**常见误区：** 把“可合并”说成所有量化后结果逐 bit 不变；忘记保存基础模型版本。

<a id="s10"></a>

### S10. Prompt tuning、Prefix tuning、Adapter 与 LoRA 如何选？

**难度 / 岗位：** 进阶；算法、应用、系统。

**作答要点：** Prompt tuning 学习输入软 token；prefix tuning 影响多层的前缀状态；传统 adapter 在主干中加入可训练模块；LoRA 修改已有线性映射的低秩增量。比较维度是任务容量、可合并性、序列/cache 开销、训练资源与服务框架兼容。软 prompt 是参数化向量，不是人工写提示词。参见 [Prompt Tuning](https://arxiv.org/abs/2104.08691)、[Prefix-Tuning](https://arxiv.org/abs/2101.00190)。

**深入追问：** 多租户加载上千个任务时，哪种存储更省、哪种更容易批处理？

**常见误区：** 只按可训练参数数量排序；认为 prefix 不占任何 KV 或上下文相关资源。

<a id="s11"></a>

### S11. DoRA、LoRA+ 各改变了什么？如何谨慎比较？

**难度 / 岗位：** 研究；后训练、研究。

**作答要点：** DoRA 将权重幅度与方向拆开，使用低秩方向更新并学习幅度；LoRA+ 研究 A/B 使用不同学习率，以改善特定宽度与优化设置下的学习动态。二者分别改变参数化和优化，不是同一种算法改名。比较时固定主干、数据、预算和调参机会，同时检查训练开销、合并支持与质量。见 [DoRA](https://arxiv.org/abs/2402.09353)、[LoRA+](https://arxiv.org/abs/2402.12354)。

**深入追问：** 如果基线 LoRA 未充分调参，能否据此得出变体普遍优越？应报告哪些成本？

**常见误区：** 把某论文平均增益直接当自己项目承诺；不区分方向与幅度更新。

<a id="s12"></a>

### S12. SFT loss 下降但回答变差，怎样排查？

**难度 / 岗位：** 进阶；后训练、应用。

**作答要点：** 先比较训练/推理模板、labels mask、EOS 和解码参数；再看训练/验证分布、重复、答案正确率与长度偏好。低 loss 可能只说明学会了模板和高频表达，未必改善任务成功。按能力切片看基线、早期和后期 checkpoint，检查过拟合与遗忘；保持独立人工盲评和可执行评测。少量高质量数据的启发见 [LIMA](https://arxiv.org/abs/2305.11206)。

**深入追问：** 如果输出更长使 judge 胜率提高，但实际解决率下降，该选择哪个 checkpoint？

**常见误区：** 只根据最后一步训练 loss 交付模型；把不一致解码配置造成的差异归因于训练。

<a id="s13"></a>

### S13. 如何生成与筛选指令数据，避免教师自我强化？

**难度 / 岗位：** 进阶；数据、后训练。

**作答要点：** 从任务 taxonomy 和真实失败样本生成多样指令，控制相似度与难度；将指令可解性、答案正确性、格式有效性分开筛选。对可执行任务使用测试/约束，对开放题使用不同来源的评判与人工抽样。保留教师版本、提示及生成参数，按任务而非文本随机拆分评测。起点见 [Self-Instruct](https://arxiv.org/abs/2212.10560)。

**深入追问：** 为什么随机拆分一批高度相似的合成题会虚高验证效果？如何检测答案风格过于单一？

**常见误区：** 将教师“解释很完整”当作事实正确；只去重 question 而不检查 answer。

<a id="s14"></a>

### S14. 知识蒸馏的 hard target 和 soft target 有何区别？

**难度 / 岗位：** 进阶；算法、压缩、后训练。

**作答要点：** hard target 以教师采样序列做监督，易落地但只观察选中的答案；soft target 用教师词表分布与学生分布的交叉熵/KL，保留相对概率，但需要 logits、词表对齐和额外计算。温度 T 的经典蒸馏常乘 `T²` 调整梯度尺度，是否适用要看目标和实现。序列蒸馏还应控制教师错误、长度偏差与任务覆盖。原理见 [Distilling the Knowledge](https://arxiv.org/abs/1503.02531)，模型级实例见 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)。

**深入追问：** 教师、学生 tokenizer 不同，能否直接逐 token KL？答通常不能，需要额外对齐或改用序列监督。

**常见误区：** 认为学生参数少就无法在某一窄任务超过教师；认为蒸馏必然需要教师全部权重。

<a id="s15"></a>

### S15. 推理轨迹蒸馏时，“长思维链越多越好”有什么问题？

**难度 / 岗位：** 研究；推理、后训练。

**作答要点：** 轨迹可能包含无效反思、错误中间步或不可验证结论。应先核验最终答案及关键步骤，再考虑多样性、长度和难度；同时保留简洁任务的直接回答，避免所有请求都产生长轨迹。评估固定 token 预算下的准确率、时延和可读性。R1 与 Qwen3 可用于讨论轨迹训练与 thinking budget，而非证明长文本本身构成推理。见 [R1](https://arxiv.org/abs/2501.12948)、[Qwen3](https://arxiv.org/abs/2505.09388)。

**深入追问：** 同样正确率下，输出长度翻倍的模型是否更好？为什么可见轨迹不能直接视为真实内部推理的忠实记录？

**常见误区：** 以“出现自我反思措辞”判定涌现新能力；只以平均输出长度选模型。

<a id="s16"></a>

### S16. 多任务 SFT 怎样处理样本量和长度不均衡？

**难度 / 岗位：** 进阶；后训练、数据。

**作答要点：** 先定义 token 级或样本级目标：token 平均会让长答案贡献更多，样本平均则令短答案 token 权重更大。对任务设置采样与损失权重，并报告任务级、语言级结果，避免大量简单任务淹没稀缺关键任务。训练任务多样性有助迁移，但最佳配比仍需消融。参考 [Scaling Instruction-Finetuned Models](https://arxiv.org/abs/2210.11416)。

**深入追问：** 100 个长代码样本与 1000 个短分类样本如何公平比较？如果 oversampling 少数任务导致重复，应怎样监控？

**常见误区：** 只看数据行数决定混合比例；把所有任务平均 loss 当作用户价值。

<a id="s17"></a>

### S17. 多适配器服务时如何管理兼容性和版本？

**难度 / 岗位：** 进阶；推理、平台。

**作答要点：** 每个适配器绑定基础 checkpoint、模块名/形状、rank、缩放、tokenizer 与训练模板；存储哈希和验收结果。服务层需考虑按需加载、热切换、并发隔离及不同 rank 的 batching 支持。多个适配器相加不是通用能力叠加定律，应检查冲突与回归。API 与合并能力随版本变化，执行时以固定版本文档为准。参见 [PEFT LoRA](https://huggingface.co/docs/peft/main/package_reference/lora)。

**深入追问：** 相同“7B”名称、不同权重修订能否共用同一适配器？何时需要合并后单独部署？

**常见误区：** 只保存 adapter 文件而无基础模型标识；以为两个独立适配器之和必然兼容。

<a id="s18"></a>

### S18. 面试中的 SFT 项目复盘应给出哪些可审查证据？

**难度 / 岗位：** 进阶；全岗位。

**作答要点：** 用具体失败触发背景，给出基础模型、数据来源与独立划分、训练配方、选择 checkpoint 的规则，以及训练前后的任务成功率、通用回归和资源成本。展示一组成功/失败样例及其判定标准，说明哪些结论来自消融、哪些只是观察。包括导出后与实际服务路径的验证，避免只有离线训练曲线。开放资产思路见 [OLMo](https://arxiv.org/abs/2402.00838)。

**深入追问：** 如果资源只够一次训练，怎样安排最有价值的基线、数据抽样和早停验证？

**常见误区：** 只有“训练了多少条、用了几张卡”；没有区分格式正确与任务正确。
