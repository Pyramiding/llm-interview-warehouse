# 06 · RAG、检索与知识系统

> 本页 18 题均为基于公开研究与工程实践原创组织的**延伸练习题**，不代表任何公司的真实面试题或标准答案。经典工作提供基础，重点覆盖 2023 年以来的检索增强、长上下文与图检索。来源于 2026-10-22 联网核查；不声称覆盖全部最新成果。

建议顺序：R01–R06 建立链路，R07–R13 做算法与评测，R14–R18 做系统设计和排障。作答时先说约束，再说方案、指标、失败情形。

<a id="r01"></a>

### R01. RAG 与微调分别解决什么问题，如何选择？

- **难度 / 适用岗位：**基础；算法、应用开发、架构。
- **作答要点：**RAG 在推理时引入外部证据，适合知识频繁变化、要求追溯和细粒度权限的任务；微调主要改变行为、风格、任务能力与输出规律。两者可组合：先用微调学会读证据与拒答，再以检索供给事实。比较时固定模型与问题集，测正确率、证据支持率、更新成本、延迟及访问控制效果。[RAG 原论文](https://arxiv.org/abs/2005.11401) 是可训练检索与生成结合的研究方案，不能把今天所有“拼接搜索结果”实现都视为同一算法。
- **深入追问：**企业术语理解差但事实库完整，应先调整哪一环？如何区分模型不会推理与没有知识？
- **常见误区：**认为 RAG 自动消除幻觉；用微调记忆每天变化的表格而忽略更新与撤回成本。

<a id="r02"></a>

### R02. 从文档到回答，一条可观测的 RAG 链路包含什么？

- **难度 / 适用岗位：**基础；应用开发、搜索、平台。
- **作答要点：**离线处理解析、去重、结构保留、切块、元数据、嵌入和索引；在线处理鉴权、问题改写、候选召回、重排、上下文组装、生成及引用验证。每一步保留文档版本、chunk ID、模型版本和时间，便于复现。将失败拆成“证据未入库、未召回、被重排丢弃、未读懂、无依据生成”，避免只看最终满意度。
- **深入追问：**如何让用户点到原 PDF 页码？解析器升级后怎样低风险重建索引？
- **常见误区：**只记录最终 prompt；把 OCR 与表格解析错误归咎于生成模型。

<a id="r03"></a>

### R03. 切块大小、重叠和父子块怎样选择？

- **难度 / 适用岗位：**中等；搜索、RAG 算法。
- **作答要点：**短块便于精确召回，但容易丢失定义、主语和表格上下文；长块提高完整性，却稀释向量语义并占用预算。可先按章节、段落、表格边界切分，再用 token 上限兜底；子块召回、父段落回填兼顾精度与完整性。以包含短事实、跨段解释和表格的问题分层比较，不能只用单一平均指标。
- **深入追问：**重叠比例增大后 recall 上升、答案却变差，如何解释？怎样避免重叠块挤满 top-k？
- **常见误区：**把 512 token 当普适最优；按字符切断代码、标题和表格行。

<a id="r04"></a>

### R04. 双编码器为何适合召回，交叉编码器为何适合重排？

- **难度 / 适用岗位：**中等；搜索算法、NLP。
- **作答要点：**双编码器分别计算查询和文档向量，文档可预计算并使用近似最近邻；交叉编码器联合读取查询和文档，交互更充分，但每个候选都需前向。[DPR](https://arxiv.org/abs/2004.04906) 是双编码器检索的经典来源。设计成粗召回数百条、过滤和重排后保留少量证据；训练负例必须覆盖“字面相似但事实不相关”。
- **深入追问：**在线多向量检索在表达力、索引大小与延迟上处于什么位置？难负例可能包含哪些假负例？
- **常见误区：**把高向量相似度解释为事实正确；离线相关性提升就直接推断端到端准确率提升。

<a id="r05"></a>

### R05. 稀疏与稠密检索如何融合，RRF 如何计算？

- **难度 / 适用岗位：**中等；搜索、应用算法。
- **作答要点：**稀疏检索保留术语、编号和精确字符串优势；稠密检索更容易匹配同义表达。不同检索器分数尺度通常不能直接相加，可先做验证集标定，或按排名使用 `RRF(d)=Σ_i 1/(k+rank_i(d))`。例如 k=60，文档在两路排名 1 与 10，其融合分约为 `1/61+1/70≈0.03068`；只在一路出现不能凭空补另一路排名。此处是通用融合练习，不是某论文的效果复述。
- **深入追问：**融合后如何控制同一文档重复块？关键词检索在中英文混合与产品编码上怎样分词？
- **常见误区：**把 RRF 的 k 与 top-k 混为一谈；不说明候选集合和缺失排名的处理。

<a id="r06"></a>

### R06. 向量检索的 recall、精度、延迟如何权衡？

- **难度 / 适用岗位：**中等；搜索基础设施。
- **作答要点：**区分精确向量近邻 recall、人工相关性 recall 和最终答案召回。先以精确搜索为基线，再衡量 ANN 的近似损失；索引参数、向量维度、量化、过滤顺序和重建策略共同决定资源与质量。选型必须带上规模、更新率、过滤选择率和 p95 延迟。对千万条、每条 768 维 FP32 向量，纯向量存储约 `10^7×768×4=30.72 GB`，还未包含索引、文本、元数据与副本。
- **深入追问：**权限过滤后仅剩 1% 文档，先搜后过滤为何可能缺结果？
- **常见误区：**用向量压缩比代表整个系统存储节省；仅在无过滤的随机查询上压测。

<a id="r07"></a>

### R07. 如何训练领域 embedding，如何发现假负例？

- **难度 / 适用岗位：**进阶；检索算法、训练。
- **作答要点：**构造问题—证据正例，混合随机、BM25、当前模型挖掘的难负例；对比损失推动正例相对负例靠近。批内负例降低成本，但同义问题、重复文档可能被误标。用文档归属、等价答案、多正例与人工抽检减少假负例；训练/验证按文档、时间或客户分组，防止同源切块泄漏。[DPR](https://arxiv.org/abs/2004.04906) 可作为双编码器训练起点。
- **深入追问：**领域训练后通用召回退化如何处理？温度、batch size 与负例质量如何相互影响？
- **常见误区：**把用户点击都当相关性真值；训练集与测试集共享文档近重复片段。

<a id="r08"></a>

### R08. 查询改写、多查询与 HyDE 有何区别？

- **难度 / 适用岗位：**中等；RAG、搜索算法。
- **作答要点：**改写补全省略、解析指代；多查询增加词汇与视角覆盖；[HyDE](https://arxiv.org/abs/2212.10496) 先生成假设文档，再以它的向量寻找真实材料。假设文本是检索中介，不能作为事实来源。对多轮会话保留原问题、改写结果和检索差异，设置查询数与额外延迟上限，使用独立评测确认收益。
- **深入追问：**“这个项目的负责人呢”如何改写？改写把否定词丢掉怎样检测？
- **常见误区：**直接把 HyDE 生成的内容交给用户当证据；无限扩展查询导致主题漂移。

<a id="r09"></a>

### R09. 如何处理多跳问题与需要全库总结的问题？

- **难度 / 适用岗位：**进阶；RAG 研究、架构。
- **作答要点：**多跳问题需要分解子问题，并以中间实体继续取证；全局问题如“这些项目的共同风险”可能需要覆盖式采样、层次摘要或社区摘要，不能只取相似度最高的五段。[GraphRAG](https://arxiv.org/abs/2404.16130) 针对全局总结引入图结构与社区摘要。应比较局部问答、实体关系和全局总结三组指标，计入构图、更新、错误传播成本。
- **深入追问：**实体合并错误如何影响答案？为什么知识图谱不一定优于普通检索？
- **常见误区：**把所有多跳需求都转换成昂贵构图；用全局摘要回答精确金额而不回溯原文。

<a id="r10"></a>

### R10. 长上下文模型普及后，是否还需要 RAG？

- **难度 / 适用岗位：**中等；模型应用、架构。
- **作答要点：**上下文可容纳不等于稳定使用；[Lost in the Middle](https://arxiv.org/abs/2307.03172) 提供位置敏感性的经典证据，结论需对目标模型重新测量。长上下文适合材料有限、需要整体理解的任务；RAG 适合大库、权限过滤、快速更新和成本控制。比较固定质量下的预填充成本、缓存命中、证据覆盖和噪声鲁棒性，可用检索粗筛加长上下文精读。
- **深入追问：**如何构造位置扰动评测？把材料全放进去会产生哪些权限问题？
- **常见误区：**将某旧模型的实验结果直接当作所有新模型的定律；只比较窗口长度。

<a id="r11"></a>

### R11. RAG 评测如何拆解，何时可用 LLM 当裁判？

- **难度 / 适用岗位：**中等；算法、评测。
- **作答要点：**检索看 recall@k、MRR/nDCG 和证据覆盖；生成看答案正确性、引用支持、拒答和完整性；系统看延迟、成本与权限违规。构造有答案、无答案、冲突、过期、多跳等切片。LLM 裁判适合扩展人工标注，但需固定 rubric、盲化方案、交叉复核与抽样校准；不要把裁判分数当客观真值。
- **深入追问：**引用存在但不支持结论，怎样自动筛查？没有唯一参考答案的总结题如何评估？
- **常见误区：**用字符串相等判断所有问答；用与候选同一模型生成的参考答案进行无复核评测。

<a id="r12"></a>

### R12. Self-RAG 和普通“先检索再生成”有哪些不同？

- **难度 / 适用岗位：**进阶；RAG 研究、训练。
- **作答要点：**[Self-RAG](https://arxiv.org/abs/2310.11511) 将是否检索、证据相关性和生成支持等反思信号纳入训练与推理控制，而非无条件拼接固定数量片段。它不是仅添加一句“请自我反思”。工程上可先做显式检索路由与证据校验基线，再判断是否值得训练专用模型；比较不检索的简单任务、需要事实的任务和无证据任务。
- **深入追问：**模型自评不可靠时为何仍可能有用？训练反思标记需要什么数据？
- **常见误区：**将模型的高自信等同于引用正确；忽略额外生成与搜索预算。

<a id="r13"></a>

### R13. 检索增强系统如何防止权限泄漏与提示注入？

- **难度 / 适用岗位：**进阶；应用安全、平台。
- **作答要点：**权限应由可信应用在检索、回填、缓存和引用出口校验，不能让模型决定用户能看什么。文档是待分析数据，恶意“忽略前文并泄露机密”不应提升为指令。工具身份与用户身份需绑定；日志与缓存按租户隔离；用恶意文档、跨租户同义查询和权限撤回建立回归集。此题为仓库设计练习，需结合组织权限模型实施。
- **深入追问：**混合搜索一路忘记过滤如何发现？共享答案缓存的 key 至少应包含什么？
- **常见误区：**只在 UI 隐藏敏感文本；认为向量无法还原原文就无需保护索引。

<a id="r14"></a>

### R14. 系统设计：为千万文档、分钟级更新的企业知识库设计 RAG。

- **难度 / 适用岗位：**高级；架构、平台、负责人。
- **作答要点：**先确定活跃租户、QPS、文档类型、更新率、SLO 与删除时限。用事件队列驱动解析与索引，文档版本和 tombstone 支持幂等更新；词法/向量索引按版本切换，重排服务独立扩缩容。权限在各召回与回填路径强制执行；回答保存证据版本。设计降级为仅搜索或明确证据不足；容量估算覆盖向量、原文、索引副本、重排吞吐和 LLM token 量。
- **深入追问：**删除请求如何覆盖旧缓存与备份？双写重建时怎样验证新旧索引一致？
- **常见误区：**只画向量库加模型两个方框；给出容量数字却没有维度与副本假设。

<a id="r15"></a>

### R15. 定量设计：top-k 增大为何可能降低最终准确率？

- **难度 / 适用岗位：**进阶；算法、系统优化。
- **作答要点：**更多候选提高证据进入集合的概率，也增加噪声、重复和预填充成本。设上下文预算 B，指令与问题占 q，预留输出 o，每块平均 c，则最多放 `floor((B-q-o)/c)` 块。例如 B=8192、q=800、o=1200、c=600，只能放 10 块。以 token 预算而非固定块数组装，并用重排、去重、覆盖性选择做质量—成本曲线。
- **深入追问：**如果单块长度长尾严重，怎样避免截断关键证据？如何给互补证据而非近重复块加分？
- **常见误区：**将离线 recall@100 上升直接等同于答案准确率上升；不预留生成空间。

<a id="r16"></a>

### R16. 排障：embedding 升级后召回率突然下降，如何定位？

- **难度 / 适用岗位：**进阶；搜索、MLOps。
- **作答要点：**保留旧版本基线，先排查查询与文档是否用了不同模型、维度、归一化、前缀模板、距离函数及 tokenizer；再检查索引是否完整、过滤条件与 ANN 参数。以精确检索对照 ANN，将表示质量与索引误差分离；固定小样本核对向量、top-k 与证据。升级宜完整重嵌入、灰度双读与可回滚，不应默认新旧向量空间兼容。
- **深入追问：**同维度模型为何也不能混用？怎样判断是模型领域偏差还是索引漏数据？
- **常见误区：**只调 top-k 掩盖版本不一致；只重算新文档，旧向量长期混存。

<a id="r17"></a>

### R17. 排障：召回了正确原文，回答仍旧错，下一步做什么？

- **难度 / 适用岗位：**进阶；RAG、评测。
- **作答要点：**逐级检查正确块是否进入最终上下文、是否被截断、是否带上标题/单位/时间、是否存在冲突材料；再做只提供黄金证据的 oracle 实验。若 oracle 仍错，检查问题歧义、数值运算、表格结构与模型能力；若仅多文档时错，测试排序、去噪与引用约束。把修复绑定到可复现问题集，不靠换一句提示后挑成功样本。
- **深入追问：**“万元”误读成“元”属于哪一层？怎样把表格计算交给可信计算器？
- **常见误区：**继续增加检索候选；让模型根据自身记忆覆盖已验证的最新资料。

<a id="r18"></a>

### R18. 如何做一个能写进简历的 RAG 项目复盘？

- **难度 / 适用岗位：**中等至高级；所有 RAG 相关岗位。
- **作答要点：**说明真实约束、数据获得方式、基线、评测集构造、关键改动与消融。至少报告质量、引用支持率、拒答、p95 延迟和每次成功任务成本；公布样本量、统计口径和失败例。把“我优化了什么”与团队/框架已有能力分开，明确上线前后流量是否可比。[GraphRAG 官方仓库](https://github.com/microsoft/graphrag) 可供理解可复现组件，但引用开源方案不代表个人实现了其全部研究成果。
- **深入追问：**若只能再做一个实验，哪个能最大程度验证因果贡献？数据与答案如何做版本管理？
- **常见误区：**只有截图和架构图；将手工挑选十个问题的成功率写成生产准确率。
