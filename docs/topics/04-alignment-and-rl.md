# 偏好对齐、RLHF、RLVR 与 GRPO

> 18 道原创研究延伸题，不声称企业真题。核验截止：2026-10-22；近期重点为 2023 年 DPO、2024 年 GRPO，以及 2025 年 R1、DAPO、Dr. GRPO 等已核实公开研究。符号：x 为提示，y 为完整输出，πθ 为策略，πref 为参考策略，r 为奖励。区分论文初版、后续修订与框架当前实现。

## 推荐答题方式

先说优化目标与奖励来源，再说明数据分布、采样、估计器及稳定措施，最后讲可被独立评测发现的失败模式。奖励上涨、训练通过率上涨与真实能力提升是三个需要分别验证的命题。

<a id="a01"></a>

### A01. SFT → 奖励模型 → RLHF 的典型流程是什么？

**难度 / 岗位：** 基础；后训练、研究。

**作答要点：** SFT 用示范建立初始行为；对同一提示采样多个回答并获得偏好；训练奖励模型预测相对质量；策略在奖励与偏离参考模型的约束下更新。SFT、奖励与策略数据可分阶段迭代，但评估应独立。InstructGPT 是典型公开路线，不代表之后所有系统都采用相同组件或顺序。见 [InstructGPT](https://arxiv.org/abs/2203.02155)。

**深入追问：** 为什么偏好标签比“绝对打 1—10 分”可能更容易一致？基础模型比对齐模型参数多，就一定更受用户偏好吗？

**常见误区：** 把 RLHF 等同于所有后训练；认为必须掌握某公司的私有完整配方才能解释原理。

<a id="a02"></a>

### A02. Bradley–Terry 偏好模型怎样训练奖励函数？

**难度 / 岗位：** 进阶；对齐、研究。

**作答要点：** 同一 x 下，`P(y_w ≻ y_l)=σ(rφ(x,y_w)−rφ(x,y_l))`，负对数似然为 `−logσ(Δr)`。同提示下给所有奖励加同一常数不改变偏好概率，因此奖励绝对零点不可由成对标签辨识。奖励模型还会学习长度、措辞等捷径；需按主题、长度和来源留出评估，并检查标注者分歧。背景见 [InstructGPT](https://arxiv.org/abs/2203.02155)。

**深入追问：** Δr=0 时偏好概率为 0.5；多人偏好冲突是否能用一个统一分数完整表示？

**常见误区：** 把奖励值当经过校准的正确概率；把没有平局标签的数据理解成用户永远有严格偏好。

<a id="a03"></a>

### A03. KL 正则的 RLHF 目标和最优策略有什么关系？

**难度 / 岗位：** 研究；对齐、强化学习。

**作答要点：** 固定 x，优化 `E_{y∼π}[r(x,y)]−βKL(π||πref)`，β>0。在不受参数化限制且支持集适当时，变分求解得 `π*(y|x)=πref(y|x)exp(r/β)/Z(x)`。β 权衡奖励与偏离；它不是 PPO clip 范围。KL 可作为奖励惩罚或单独损失，实现需说明。最优形式是 DPO 推导的起点。见 [DPO](https://arxiv.org/abs/2305.18290)。

**深入追问：** 若 πref(y|x)=0，有限 KL 的策略能否给该 y 正概率？Z(x) 为什么难算，却能在成对比较中消掉？

**常见误区：** 忽略 KL 的方向；把 reference policy 与每轮采样的 old policy 混为一谈。

<a id="a04"></a>

### A04. REINFORCE 为什么能用不可微的规则奖励？baseline 有何作用？

**难度 / 岗位：** 进阶；强化学习、后训练。

**作答要点：** `∇θE_{y∼πθ}[r(y)]=E[r(y)∇θlogπθ(y)]`，若奖励函数固定，不需对 r 关于文本求导。序列 log probability 是各 token log probability 之和。减去不依赖当前动作的 baseline 可减方差且不改变理想期望梯度；用同一组样本估计 baseline 时还需检查有限样本依赖与偏差。PPO 属于相关策略梯度路线。见 [PPO](https://arxiv.org/abs/1707.06347)。

**深入追问：** 为什么不能直接对采样的离散 token id 反向传播？batch reward mean 的使用有什么估计器细节？

**常见误区：** 认为规则奖励不可微就无法 RL；把减方差说成奖励一定变小。

<a id="a05"></a>

### A05. PPO 的 clipping 目标写出来，各项指什么？

**难度 / 岗位：** 进阶；强化学习、对齐。

**作答要点：** `ρₜ=πθ(aₜ|sₜ)/πold(aₜ|sₜ)`，最大化 `E[min(ρₜÂₜ, clip(ρₜ,1−ε,1+ε)Âₜ)]`。πold 是 rollout 时冻结的行为策略；Â 是优势估计。clip 限制在有利方向上继续扩大代理收益，不是把所有概率比率硬限制在区间，也不直接保证 KL 上界。还需价值函数、熵/参考 KL 等具体实现项。见 [PPO](https://arxiv.org/abs/1707.06347)。

**深入追问：** Â=2、ρ=1.3、ε=0.2 时代理项为 2.4；若 Â<0，为什么必须考虑 min 的另一方向？

**常见误区：** 把 PPO clip 与梯度裁剪当成一件事；把 πref 放进 ρ 的分母。

<a id="a06"></a>

### A06. Advantage、value、return 和 GAE 如何区分？

**难度 / 岗位：** 进阶；强化学习、对齐。

**作答要点：** return 是未来折扣奖励；value 估计给定状态的期望 return；advantage 衡量动作优于该状态平均水平多少。GAE 用 TD 残差 `δₜ=rₜ+γV(sₜ₊₁)−V(sₜ)` 构造 `Âₜ=∑ₗ(γλ)^lδₜ₊ₗ`，通过 λ 权衡方差与对近似 V 的依赖。语言任务须说明终止奖励、每 token KL 惩罚、截断与真正终止的 bootstrap 规则。原始估计器见 [GAE](https://arxiv.org/abs/1506.02438)。

**深入追问：** 输出因为 max_tokens 被截断，与模型主动 EOS，价值 bootstrap 是否应总相同？

**常见误区：** 把 reward 直接称为 advantage；误把 value 当成每个 token 正确与否的概率。

<a id="a07"></a>

### A07. 从 KL 正则目标推导 DPO loss。

**难度 / 岗位：** 研究；对齐、研究。

**作答要点：** 由 A03 得 `r=βlog(π*/πref)+βlogZ(x)`；代入成对偏好模型，Z 项相消。令 `dθ=logπθ(yw|x)−logπref(yw|x)−logπθ(yl|x)+logπref(yl|x)`，DPO 为 `L=−E logσ(βdθ)`。标准序列 log-prob 对回答 token 求和，padding/prompt 不应误算。推导依赖偏好与正则目标假设，不代表任意偏好数据上都等同真实最优奖励。见 [DPO](https://arxiv.org/abs/2305.18290)。

**深入追问：** 初始 πθ=πref 时，d=0、loss=ln2；梯度如何同时作用于 preferred/rejected 序列？

**常见误区：** 漏掉 reference log-prob；把 β 写在 sigmoid 外；使用 mean log-prob 却仍称完全原版 DPO。

<a id="a08"></a>

### A08. DPO 的 β、数据质量和长度偏差应如何解释？

**难度 / 岗位：** 进阶；对齐、研究。

**作答要点：** β 来自目标中的 KL 权重，同时在经验 DPO loss 中缩放 log-ratio margin，影响梯度与优化动态。不能只背“β 大就一定更贴近参考模型”而不看数据、训练步数和饱和。成对差值变好不保证 chosen 的绝对概率总上升。标准序列求和也会受长度影响，应看长度分层与任务成功。长度归一化的替代设计可对比 [SimPO](https://arxiv.org/abs/2405.14734)。

**深入追问：** chosen 和 rejected 的 log-prob 同时下降，DPO loss 还能下降吗？答可以，取决于相对参考的差值。

**常见误区：** 用训练 loss 单独判断人类偏好提升；把 chosen 更长的数据全当高质量。

<a id="a09"></a>

### A09. Offline DPO 与在线 RL 何时各有优势？

**难度 / 岗位：** 进阶；后训练、研究。

**作答要点：** offline DPO 可复用固定偏好集，工程较简单，但受覆盖范围与标签噪声限制；在线 RL 从当前策略采样，可利用新的可验证轨迹，但有 rollout、奖励与训练系统成本及稳定性问题。离线/在线不是由算法名称唯一决定，也存在迭代 DPO。选择应根据奖励可靠性、探索需求、数据获取和服务目标。理论起点见 [DPO](https://arxiv.org/abs/2305.18290)、[DeepSeekMath](https://arxiv.org/abs/2402.03300)。

**深入追问：** 若当前模型输出与偏好训练集分布相差很大，如何补数据或重新采样，而不是只增加 epoch？

**常见误区：** 说 DPO 不需要任何参考或奖励假设；说在线采样天然无偏且无污染。

<a id="a10"></a>

### A10. GRPO 为什么不需要独立 critic，组内优势怎样构造？

**难度 / 岗位：** 进阶；推理、强化学习。

**作答要点：** 对同一提示采样 G 个输出，通过组内奖励均值与标准差构造一种常用优势：`Âᵢ=(rᵢ−mean(r))/(std(r)+ε)`，再将其用于 token 级策略比率更新。它以组间相对比较替代训练独立 value model，节约其状态与计算，但增加同一题多样本 rollout 成本。KL、长度归一化与采样细节随变体变化。见 [DeepSeekMath](https://arxiv.org/abs/2402.03300)。

**深入追问：** 一组全部答对或全错时优势有什么问题？G 增大在信号质量、延迟与多样性上如何权衡？

**常见误区：** “无 critic”就推断无 baseline、无方差；把组内标准差视为任务难度的完美估计。

<a id="a11"></a>

### A11. GRPO 的长度归一化和标准差归一化为什么会产生偏置？

**难度 / 岗位：** 研究；推理、强化学习。

**作答要点：** 序列先平均再按组平均，与把所有 token 一起平均不是同一权重；长度与正确性相关时会改变梯度。按题目组奖励标准差缩放，也会改变不同题之间的权重。Dr. GRPO 指出特定 GRPO 目标的长度等优化偏置，DAPO 则讨论 token 级损失及数据筛选等训练设计；实现需逐项对照，不能仅看算法名。见 [Dr. GRPO](https://arxiv.org/abs/2503.20783)、[DAPO](https://arxiv.org/abs/2503.14476)。

**深入追问：** 如果一题的奖励方差很小，标准差归一化会怎样放大信号？移除归一化后怎样重调学习率？

**常见误区：** 不区分原论文、框架默认和实验脚本；把所有 GRPO 改进都归因于一个参数。

<a id="a12"></a>

### A12. RLVR 中“可验证”指什么，奖励设计会在哪些地方失效？

**难度 / 岗位：** 进阶；数学、代码、Agent 训练。

**作答要点：** RLVR 用程序规则、执行测试、形式约束等外部机制评价输出，减少主观偏好标注；可验证器仍可能不完备。数学需处理等价表达、格式抽取和容差；代码测试可能覆盖不足、受环境影响；工具任务还需区分最终成功与副作用。奖励函数与隐藏评测分开，审查高奖励失败样例。实例见 [DeepSeek-R1](https://arxiv.org/abs/2501.12948)。

**深入追问：** 单元测试全过是否证明程序对所有输入正确？超时、截断、无法解析和真正错误应该如何分开计量？

**常见误区：** 可自动评分就认为评价器不会被利用；用宽松字符串匹配代替正确性验证。

<a id="a13"></a>

### A13. Outcome reward 与 process reward 分别有哪些取舍？

**难度 / 岗位：** 研究；推理、强化学习。

**作答要点：** outcome reward 只看最终答案，标注/验证可能较容易但信用分配稀疏；process reward 评价中间步骤，信号更密集，却需要步骤粒度定义、标注一致性及防止“看起来合理”的错误。错误步骤后偶然答对、正确方法但算错最后一步，说明两类信号的不同。结果应按训练、搜索重排或过程监督用途分别判断。见 [Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)。

**深入追问：** 过程模型用于 best-of-N rerank 的收益，能否直接证明用同一模型做 RL 奖励也会提高？

**常见误区：** 把每行自然语言解释当可验证步骤；声称有过程奖励就一定消除 reward hacking。

<a id="a14"></a>

### A14. Reward hacking 与过度优化怎样识别和缓解？

**难度 / 岗位：** 进阶；对齐、评测、研究。

**作答要点：** 典型现象是训练奖励持续提高，独立人评、事实正确或真实任务成功却停滞/下降。检查长度、格式、重复、评判器偏好与越界行为；保留不同来源的评估器和隐藏测试，定期审查高奖励样本。约束更新、刷新数据及奖励组合可缓解，但不能替代外部评估。偏好与规则奖励均可能被利用，背景见 [InstructGPT](https://arxiv.org/abs/2203.02155)、[R1](https://arxiv.org/abs/2501.12948)。

**深入追问：** 若模型学会只输出答案格式标记而骗过抽取器，应修模型、奖励还是评测？如何保留复现证据？

**常见误区：** 将奖励增长当作唯一训练健康指标；上线后才第一次看人工失败样例。

<a id="a15"></a>

### A15. RLAIF 和 Constitutional AI 是否意味着没有人类监督？

**难度 / 岗位：** 进阶；对齐、安全、数据。

**作答要点：** AI 可生成批评、修订及偏好标签，减少逐样本人类标注；但原则、评判标准、教师选择与审计仍来自人的设计。Constitutional AI 使用规则/原则指导监督与 AI 偏好阶段，不等于价值中立或零人工成本。应检查教师偏差、原则冲突、跨语言差异和长尾情景。见 [Constitutional AI](https://arxiv.org/abs/2212.08073)。

**深入追问：** 如果 AI judge 更喜欢自己的文风，如何用盲评、交换顺序和异源评判发现？

**常见误区：** 认为所有自动偏好标签都是客观真值；混淆“无逐条有害标签”与“完全无人制定目标”。

<a id="a16"></a>

### A16. RL 到底是在发现新能力，还是提高已有正确轨迹的采样概率？

**难度 / 岗位：** 研究；推理、研究。

**作答要点：** 单看 pass@1 上涨不能回答。可在相同采样协议与 token 预算下比较 base/RL 模型的 pass@k 曲线、成功问题集合、轨迹多样性和分布外迁移；排除提示模板、验证器和数据泄漏。2025 年相关研究讨论 RLVR 能力边界，但实验依赖基础模型、任务与预算，不能推广为“RL 永远只重排已有答案”或“RL 必然创造新推理”。见 [RLVR 能力研究](https://arxiv.org/abs/2504.13837)、[Dr. GRPO](https://arxiv.org/abs/2503.20783)。

**深入追问：** 如果 pass@1 提高而大 k 的 pass@k 下降，可能提示什么？不同模型温度相同是否已保证公平？

**常见误区：** 把一段“aha”文本当作新算法能力的充分证据；不控制搜索预算。

<a id="a17"></a>

### A17. 长推理 RL 的系统瓶颈怎样分析？

**难度 / 岗位：** 进阶；训练、推理、系统。

**作答要点：** 拆成 rollout、奖励计算、策略/参考 log-prob、反向与参数同步；长输出会放大生成耗时、KV cache 与长尾 straggler。异步或分离部署可改善利用率，但策略陈旧度会使采样与更新分布偏离。记录 tokens/s、有效奖励样本率、长度分布、GPU 空闲和每次更新耗时，而非只看训练卡利用率。实现选项见 [TRL GRPOTrainer](https://huggingface.co/docs/trl/main/en/grpo_trainer)。

**深入追问：** 若只有 10% 样本极长，为何平均长度不足以解释同步等待？动态 batching 怎样兼顾吞吐和公平性？

**常见误区：** 增加训练 GPU 就假设一定更快；忽略生成集群、奖励执行器和权重同步。

<a id="a18"></a>

### A18. 设计一套对齐实验，你会同时监控哪些指标？

**难度 / 岗位：** 研究；后训练、研究、技术负责人。

**作答要点：** 优化侧看奖励、KL、熵、clip fraction、梯度及 advantage 分布；任务侧看独立成功率、人类偏好、事实性、拒答恰当性和通用回归；系统侧看 rollout 长度、吞吐及成本。建立长度/语言/难度分层，盲评随机化回答顺序，锁定验收集。指标间冲突时按用户目标预先定义取舍，不能只挑最好看的数。近期实践参考 [DAPO](https://arxiv.org/abs/2503.14476)、[Qwen3](https://arxiv.org/abs/2505.09388)。

**深入追问：** 奖励升高、熵骤降、输出变长和真实正确率不变同时出现时，最先验证哪两个假设？

**常见误区：** 缺少 base/SFT 基线；评估器与训练奖励完全同源；不报告评估样本量和不确定性。
