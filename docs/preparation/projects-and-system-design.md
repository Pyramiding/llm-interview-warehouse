# 项目深挖与系统设计：10组原创练习

[返回首页](../../README.md) · [按岗位路线](learning-paths.md)

以下是根据公开面经中的考察方式设计的原创场景，不是任何企业的原题或真实项目经历。答题必须替换成自己的事实，不能把模板数字写进简历。

## 通用回答顺序

先说业务目标与硬约束，再给朴素基线、方案、验证、上线、失败与责任边界。报数字时同时交代分母、时间窗、采样、样本量、成本、模型与评测版本。离线提升不能自动推出线上收益。

<a id="j01"></a>

### J01. 给企业一万份PDF做问答，你如何从零落地？

- **难度/岗位：** 中；RAG、应用算法、平台。
- **作答要点：** 先辨别扫描件、表格、更新频率、权限与问题类型；建立文档ID、版本和解析质量检测。用关键词/稠密召回加基础提示作基线，再按失败类型增加重排、父子块、结构化检索或微调。评测应覆盖找不到、过时、矛盾、多跳、无权限及应拒答问题。输出引用必须落到具体证据，索引删除和权限变更要传播到缓存。
- **追问：** 为什么不直接放整篇？若答案跨表格与附录？如何定义召回标签？
- **误区：** 只回答“接向量库”；把检索相似度当答案可信概率。
- **评分证据：** 一条从PDF到最终引用的可追踪样例，以及错误归因表。

<a id="j02"></a>

### J02. 客服Agent会查询订单并执行退款，怎么设计？

- **难度/岗位：** 中/高；Agent、后端。
- **作答要点：** 将理解、计划、查询和业务写入分开，服务端鉴权并限制金额/对象/操作范围；模型输出先过schema和业务校验。执行使用幂等键、状态机、事务或补偿机制；超时后先查执行状态，防止重复退款。高影响操作有业务规定的确认节点，工具结果中的文字不改变权限。保留脱敏轨迹及审计证据。
- **追问：** 模型重复调用怎么办？用户取消时已执行了一半？
- **误区：** 以system prompt代替授权，或认为工具调用成功就等于业务正确。
- **评分证据：** 重试、超时、重复请求和权限绕过的演练。

<a id="j03"></a>

### J03. 模型上线后答案变差，你如何定位？

- **难度/岗位：** 中；应用/评测/运维。
- **作答要点：** 先确认变化来自模型、提示、检索索引、数据分布、流量路由还是判分器。固定版本回放相同请求，并按业务、长度、语言、检索命中与工具链分层。对照输入、上下文、输出和工具记录，剥离服务失败与模型失败；在明确影响后回滚或降级，再做有对照修复。
- **追问：** 离线指标没变但用户负反馈增加？日志因隐私不能保存原文？
- **误区：** 一看到幻觉就重新训练，或只看平均值。
- **评分证据：** 可复现的最小错例和变更时间线。

<a id="j04"></a>

### J04. 7B模型微调后通用能力下降，应做什么？

- **难度/岗位：** 中；SFT、后训练。
- **作答要点：** 检查模板、tokenizer、label mask、padding、数据污染和评测协议。分离训练错误、域偏移和遗忘；记录目标域与通用保留集的共同变化。比较较小学习率、早停、数据混合、PEFT和训练步数，按统一资源预算消融。仅在可信评测上定义退化，不用几条主观对话下结论。
- **追问：** 训练loss下降为什么无效？多任务数据要怎么配比？
- **误区：** 认为LoRA绝不会遗忘，或用测试集反复调参。
- **评分证据：** 多个checkpoint的双域指标与错误类别。

<a id="j05"></a>

### J05. GRPO的奖励涨了，但真实任务成功率没涨？

- **难度/岗位：** 高；RL、推理研究。
- **作答要点：** 审计奖励函数覆盖和漏洞，检查格式、长度、重复、解析器、工具可用性与通过样本选择。用独立评测器、人工抽查和未见任务区分reward hacking与泛化。统一采样次数和token预算比较，观察组内方差、裁剪比例、KL及策略熵；修改奖励后保留旧奖励的回归集。
- **追问：** 奖励全相同的组会怎样？如何避免只会变长？
- **误区：** 将训练reward等同于客观正确率。
- **评分证据：** 一个奖励高但答案错的最小反例，以及修复前后对照。

<a id="j06"></a>

### J06. 推理延迟突然升高，显存却没满？

- **难度/岗位：** 高；推理/Infra。
- **作答要点：** 拆分排队、tokenize、prefill、decode、工具等待与网络；观察输入输出长度分布、批策略、缓存命中、GPU利用和通信。按稳定到达率做开环负载，区分服务时间和排队时间，检查p95/p99与超时。Profiler用于验证瓶颈，再选择调度、批量、kernel、并行或缓存策略。
- **追问：** 吞吐升高但首token变慢？长短请求如何隔离？
- **误区：** 只报tokens/s，忽略并发、输入长度、SLO及失败请求。
- **评分证据：** 固定负载下的延迟分解和资源曲线。

<a id="j07"></a>

### J07. 分布式训练扩卡后反而变慢？

- **难度/岗位：** 高；分布式训练。
- **作答要点：** 区分强扩展与弱扩展；固定全局batch时检查每卡工作量、通信计算比、pipeline bubble、数据加载和慢节点。定位collective等待、拓扑和跨机带宽，再比较并行切分与重计算策略。记录有效训练tokens/s、有效算力利用、稳定性和成本，确认数值与训练配方可比。
- **追问：** 梯度累积如何改变通信？某rank偶发慢如何发现？
- **误区：** 以GPU数量线性外推速度，或只统计最快step。
- **评分证据：** 不同规模下的step分解与相同任务质量。

<a id="j08"></a>

### J08. 多模态模型在截图任务好，在真实相机输入差？

- **难度/岗位：** 中/高；VLM/具身。
- **作答要点：** 按光照、透视、分辨率、运动、遮挡、OCR和设备做分层。检查预处理、crop和token预算造成的信息丢失；用同一内容的受控图像干预拆分视觉感知与语言推断。训练集可增加覆盖，但评测保留未见设备与环境；具身场景还需物理安全和行动延迟评测。
- **追问：** 直接提高分辨率一定有用吗？模型靠文本先验猜对怎么办？
- **误区：** 以总体准确率掩盖关键条件失败。
- **评分证据：** 受控扰动与跨域评测矩阵。

<a id="j09"></a>

### J09. Coding Agent通过了单元测试，为什么还不能合并？

- **难度/岗位：** 中/高；代码模型/Agent。
- **作答要点：** 测试可能覆盖不足、被修改、环境不真实或存在数据泄漏。验证需求、接口兼容、依赖、安全、性能与构建；用独立隐藏测试、差异审查和人工复核。运行环境隔离，限制凭证与网络，输出补丁、执行轨迹和验证证据；工具执行成功与任务完成分别记录。
- **追问：** 测试也由同一个模型生成？网络偶发失败怎么判分？
- **误区：** 通过测试等于程序语义正确，或把所有失败算模型失败。
- **评分证据：** 一个通过现有测试但违反需求的反例。

<a id="j10"></a>

### J10. 如果入职后要独立做一项研究，你怎么选题？

- **难度/岗位：** 高；研究/算法。
- **作答要点：** 用已观察失败定义问题，列出最接近工作、可证伪假设、可测量效果和预算。先做最小基线与数据审计，再设计单变量消融、反例、跨数据集和成本对照。规定中止标准，保留负结果；将方法贡献、数据贡献与工程收益拆开归因。结果不支持假设时应改结论。
- **追问：** 无额外算力怎么办？只有一个百分点提升如何判断可信？
- **误区：** “把热门方法A加到B”就视为研究贡献。
- **评分证据：** 一页实验计划，包括失败后如何决策。
